# Architecture

This file describes the code **as it is now**. The target layout is in [SPEC.md §2](SPEC.md#2-architecture); update this file whenever a slice changes the structure.

## Workspace

A Cargo workspace (`Cargo.toml`) with two crates. Shared dependency versions, package metadata and lints live in the root `Cargo.toml` (`[workspace.dependencies]`, `[workspace.package]`, `[workspace.lints]`); each crate opts in with `.workspace = true` / `[lints] workspace = true`.

| Crate | Path | Kind | Role |
|---|---|---|---|
| `rappel-core` | `crates/core` | library | All logic. No UI dependency, testable with plain `cargo test`. |
| `rappel` | `crates/app` | binary | GTK4 + libadwaita front end. Talks to core only. |

`third_party/ratex-cairo` is a vendored copy of the `ratex-cairo` crate with `cairo-rs` bumped to 0.22 (ADR 0021, `VENDORED.md` there). It is not a workspace member (`exclude = ["third_party"]`) and is used through `[patch.crates-io]`.

Dependency direction: `rappel` → `rappel-core`, never the reverse. `rappel-core` must not depend on gtk4, glib, gio, libadwaita or anything UI.

### `rappel-core` today

Only what a front end or `examples/` uses is `pub`; everything else is `pub(crate)`, and code that only tests need is `#[cfg(test)]` (e.g. `is_valid_app_id`). Make an item `pub` in the slice that first needs it outside the crate.

- `src/lib.rs`: the app name and ID constants (its tests check `APP_ID` the way `g_application_id_is_valid` does); re-exports `Error` and `Result`.
- `src/test_support.rs` (test builds only): helpers shared by several modules' tests: `T0`, `DAY_MS`, `scheduled`, `answer`, `schedule_table`, `with_suffix`, `within` (runs hostile input on a 512 KiB stack; fails the test past a CPU-time limit, or past a separate wall-clock hang timeout, `hang_limit`; ADR 0025, ADR 0049), `fastest` (the least CPU time of a few runs), and the time-bound helpers of ADR 0049: `thread_cpu_time`, `cpu_time_between` and `cpu_time_of` (the thread's CPU time, from `/proc/thread-self/schedstat`, else `stat`, else the wall clock; a clock that does not move counts as missing), `slowdown` (how much slower than the machine the bounds were set on this thread runs now, from a reference workload) and `cpu_within` / `assert_cpu_within` (a CPU time checked against a bound at that speed, through the pure `judge`). `RAPPEL_TIMINGS=1` prints the times; `Hook` and `set_hook` (a test hook set until its guard drops: `import::BEFORE_READ`, the Anki import's `AFTER_CARD`, `BEFORE_COMMIT`, `BEFORE_CHECK`). Use them instead of a local copy, and never a wall-clock bound in a test.
- `src/error.rs`: the crate-wide `Error` enum (`thiserror`) and `Result` alias. `Random` boxes its cause so `getrandom` stays out of the API; `rusqlite` and `fsrs` errors stay visible (ADR 0015).
- `src/data_dir.rs`: `resolve_data_dir` (pure; takes a `DataDirEnv` and a `BuildProfile`) and `ensure_data_dir` (creates a directory with mode `0700`). Debug builds refuse the release directory and the pre-rename `cards` one. See ADR 0004 and ADR 0020.
- `src/id.rs`: `IdGen`, strictly increasing `UUIDv7` strings (a 122-bit counter with random low bits; `observe` raises it above an id read from the database). See ADR 0008. `uuid_v7_value` checks ids from outside (an import, ADR 0017) and gives their 122-bit value, which compares as the string does (ADR 0053); `format_id` turns a value back into its string.
- `src/time.rs`: `now_ms` (UTC milliseconds), `utc_parts` (calendar fields from milliseconds) and its inverse `utc_ms`.
- `src/domain/`: shared types, `name_key` (the uniqueness key of deck and tag names; `deck_name_key` is an alias), and the length limits shared by the store and the import (`MAX_DECK_NAME_BYTES`, `MAX_CARD_SIDE_BYTES`, `deck_name_fits`, `card_side_fits`, `CardSide`; ADR 0018): `Deck`, `DeckSummary` (deck, new/due counts, card, suspended and held-back counts, and the next study change; ADR 0041), `Card` (with `suspended`, ADR 0035), `Grade` (Fail/Pass), `ReviewEvent` (one log entry, with `EventKind`: `Review(Grade)`, `Reset` or `Undo { undoes }`, ADR 0028), `Phase`, `CardState` (`New` or `Scheduled(Schedule)`), `Settings` with its defaults, ranges and `check_*` functions and `SettingKey`, the stored keys (`domain/settings.rs`, ADR 0027, 0052), and `Tag` with `check_tag_name` and `MAX_TAG_NAME_BYTES`, `TaggedCard`, `parse_tag_field` (a comma-separated field to names) and `search_key` (the accent- and case-insensitive key for suggestions) (`domain/tag.rs`, ADR 0029, 0031).
- `src/scheduling/`: FSRS scheduling (ADR 0006), using the `fsrs` crate.
  - `mod.rs`: `Scheduler` (desired retention, default FSRS-6 parameters; built per transaction from the stored retention by `storage::settings::scheduler_in`, ADR 0027). `schedule(card_id, state, grade, now)` gives the state after one review; `rebuild_state(card_id, events)` replays a card's log: `surviving` drops undos and the entries they cancel and orders the rest, then reviews fold `schedule` and a reset gives New (ADR 0028). 10-minute step for new and failed cards; elapsed days are rounded 24-hour periods. A Pass on a review card is at least elapsed + 1 days, before and after fuzz (ADR 0009).
  - `fuzz.rs`: deterministic interval fuzz (Anki's ranges, seeded from card id + review count).
  - `session.rs`: the study session, pure (no SQL, no clock): `StudyInput`, `interleave` (new cards spread evenly among reviews), `Session` (`next(now)`: due step cards, then the queue, then step cards up to 20 minutes early; `skip` drops a card without counting it and `put_back` brings it back as the next one (suspend and delete during review, ADR 0037); `graded` re-queues cards left in the 10-minute step and remembers what it changed, so `last_answer` / `undo_last` take the newest answer back exactly and pin that card as the next one, `forget_answers`; ADR 0030), `Summary`, `capped` (60 s), `allowance` (what is left of a daily limit). The module is crate-private; `scheduling` re-exports what the app uses (`StudyInput`, `Due`, `Session`, `Summary`, `capped`). Tests in `session/tests.rs`. See ADR 0014.
  - `tests.rs`: FSRS reference values and property tests (rebuild = review-by-review; with undos and resets, rebuild = the fold of the counted reviews, #11).
- `src/content/`: card Markdown → `Document`, a UI-agnostic block/inline tree, with `pulldown-cmark` (ADR 0019). No UI.
  - `mod.rs`: the tree (`Document`, `Block`, `Inline`, `ImageTarget`, `Align`) and `MAX_DEPTH` (16), the nesting cap. An image whose target is a `media:` reference to an image kind is `ImageTarget::Media(MediaRef)`, a link to an audio kind is `Inline::Audio` (ADR 0054); `media_refs(md)` lists every valid reference of a side's image and link targets, each once, in order.
  - `parse.rs`: `parse(md)`, a stack of open containers over the parser's events. Raw HTML becomes literal text, NUL becomes U+FFFD, `$$…$$` alone in a paragraph becomes a `DisplayMath` block, inline math closed by a `$` followed by a digit is text (`$5-$10`), and containers past the cap are flattened into the deepest one.
  - `plain.rs`: `plain_text` (no syntax, for screen readers) and `search_text` (the plain text folded by `domain::search_key`, what the search index holds, ADR 0035) and `plain_summary` (one line, at most `PREVIEW_CHARS` = 200 characters, from the first 16 KiB, for the card list) and `one_line_summary` (the same from a `plain_text`).
  - `tests.rs`: each construct, untrusted HTML, dollars, the cap, property tests (never panics, within the cap), and 1 MiB hostile sides (`hostile_sides`) and random syntax repeated to 256 KiB, parsed within a time bound on a small stack, with node and text counts bounded by the input (ADR 0025).
- `src/media/`: the media store (ADR 0054) and its trash (ADR 0057). No UI.
  - `mod.rs`: `MediaRef` (a SHA-256 and a kind; `parse` of a `media:<64 lowercase hex>.<ext>` URL, `file_name`, `reference`), `MediaProblem` (empty, not media, not an image, not audio, damaged audio, more than plain audio, too large), `hex` / `parse_hex`.
  - `kind.rs`: `MediaKind` (PNG, JPEG, WebP, GIF, Ogg with Opus or Vorbis, MP3, M4A, WAV; one extension and one MIME type each; `detect` from the first `DETECT_BYTES` (512) only), `IMAGE_MAX_BYTES` (10 MB) and `AUDIO_MAX_BYTES` (20 MB).
  - `store.rs`: `Store::add_media` / `add_media_bytes` (through `ingest_then`: a new temporary file in `<data dir>/media/`, the kind from the first bytes, capped and hashed while copied (`copy_capped`; an audio file is also kept in memory and must pass `check_structure`), synced, then, under the database's write lock (`ingest_then`, ADR 0057), named `<sha256>.<ext>` by a hard link that never replaces a file; a damaged file of that name is kept under a second name), `MediaBatch` (an import's new files: each copied and checked as `ingest_then` does, then synced together, 128 at a time on up to 64 threads, before any is named; the folder synced once at `finish`; unnamed ones removed when dropped; ADR 0063), `insert_media_row` (the `media` row, the first `created_at` kept), `Store::add_image` and `add_audio` (the editor's Insert Image… and Insert Audio…: a file of the other kind refused as `NotImage` / `NotAudio` before anything is written, then `add_media`, ADR 0056; ADR 0055), `Store::media_path`, `Store::media_folder`, `sync_folder`. Folder `0700`, files `0600`.
  - `dimensions.rs`: `image_size`, an image's width and height from its header (PNG `IHDR`, a JPEG's first `SOFn`, WebP `VP8 ` / `VP8L` / `VP8X`, a GIF's screen and first image), read before anything decodes it (ADR 0063); tests with Pillow's images in `fixtures/images/` (their README has the script).
  - `color.rs`: `without_color_profile`, an image without its ICC profile (PNG `iCCP`, JPEG `ICC_PROFILE` segments, WebP `ICCP`), which glycin would unpack into the app's process and parse there with lcms2 (ADR 0063).
  - `structure.rs`: `check_structure` (ADR 0056), whether a whole audio file is plain audio of its kind, and `audio_payload`, the part of it a player is given (an MP3's frames without its tags, ADR 0062): MP3 frames after ID3v2 tags (an APE tag whose items fill its size and an ID3v1 tag at the end), one Ogg Opus or Vorbis stream with every page's CRC, a RIFF WAVE of PCM or float, M4A boxes from an allow-list per parent (no compressed movie, reference, redirect, fragment or other track). Pure, one pass, never panics; `structure/tests.rs` with real files from `fixtures/` (made with GStreamer's encoders) and hostile ones (playlists and manifests behind an ID3 tag, chained Ogg, M4A redirects).
  - `used.rs`: what a database uses (ADR 0057): `side_hashes` (`content::media_refs` plus any `media:` + 64 hex digits in the text), `card_hashes` (every card, live or deleted; only sides with `media` or `&` are parsed), `row_hashes` (none without a `media` table, as in old backups), `used_hashes`.
  - `trash.rs`: unused media and the trash `<data dir>/media-trash/<YYYY-MM-DD>[-N]/` (ADR 0057): `Store::unused_media` (`UnusedMedia`), `Store::clean_up_media` (one write transaction: the unused set found again, renames into a free place of the day's folders, syncs, rows deleted; on failure the rows roll back and the files move back; a `Mover` and a hook before the commit are injected by tests), `Store::undo_clean_up` (`CleanedUp`), `recover_rows` (at open), `recover_all` (restore, import, startup), `recover_refs` (card writes); a file comes back only if its content has its name's hash; unreadable trash folders are skipped, `trash_day` (a clean-up's folder dated the latest of today, the newest folder and the database's `latest_time`), the purge (`purgeable`: the clock 31 days after the folder's date and the database's newest user action 30 days after it; `read_copies`: every backup, the waiting restore copy and the other database copies, read-only, an unreadable backup blocking it; the files deleted under the write lock: the only deletion of a user's media file) and `Store::tidy_media_trash` (`TrashTidied`).
  - `tests.rs`: each kind, hostile signatures (SVG, HTML, polyglots, video), references, the store's files and rows, an existing file never overwritten, the table's CHECKs. `trash_tests.rs`: what is unused, every crash window of a clean-up, undo, an add and a clean-up on two connections, bringing back (open, restore, import, card writes), the purge (30 days, backups, unreadable backups, the database's own use), hostile names, the 20,000-card time bound.
- `src/stats/`: statistics over the log, pure (ADR 0032).
  - `mod.rs`: `DayGrid` (strictly increasing day starts from the caller; `day_of` by binary search), `DayActivity`, `Stats` (`Stats::compute`: days, pass rate, forecast, overdue, scheduled cards, expected retention), the pure pieces (`activity_by_day`, `pass_rate`, `due_forecast`, `retrievability` with the `fsrs` crate's `current_retrievability`, `expected_retention`) and two rules for one card's log: `counted_reviews` (its memory side: after the last surviving reset, for a card's reps) and, in tests, `activity_reviews` (every review no undo cancels; ADR 0032).
  - `card.rs`: `CardInfo`, `HistoryEntry` (`Review` / `Reset`) and `card_info`, which replays the surviving log with the scheduler.
  - `tests.rs`: bucket edges, 23- and 25-hour days, forecast, retrievability against the scheduler's interval, hand-made logs, property tests of the grid.
- `src/interchange/`: export and import of the whole database as a `.rappel` file (ADR 0017; ADR 0020 for `.cards`, which still imports), with its media files (ADR 0054), and the import of Anki packages (`anki/`, ADR 0061). The import streams the file and keeps compact notes, so its memory is bounded (ADR 0053). No UI.
  - `mod.rs`: the public types (`ExportSummary` (with the media written and those missing or damaged), `ImportPlan` (the summary, a fingerprint of the file and a digest of the decisions, no content) and its `ImportSummary` with `TableCounts` and `Conflict`s, `ImportReport`, `ImportProblem` / `FieldProblem` for a refused file; the Anki import's types re-exported, and `file_kind`, which tells a Rappel export from an Anki package by extension, else content) and the internal `Limits` (archive 2 GiB, 100,000 entries, a 16 MiB central directory, 256 MiB of JSON, one image 10 MB and one audio file 20 MB for the media import, text sizes).
  - `format.rs`: the serde types of `cards.json` (`FORMAT_VERSION` 2), fields in file order, unknown fields denied: decks, cards (with `suspended`, defaulting to false when a file lacks it, ADR 0035), tags, card tags, log entries (`kind`, `grade`, `undoes`), the typed `SettingsRecord` and `MediaRecord` (`hash`, `mime`, `bytes`, `created_at`, ADR 0054); `Document`, the whole file, which export writes. Version 1 (`EARLY_TEST_VERSION`) is refused, not read (ADR 0017).
  - `archive.rs`: writes the zip deterministically with the `zip` crate (`ArchiveWriter`: `cards.json`, `media/`, then each media file `media/<sha256>.<ext>` stored, fixed timestamp and permissions). `Archive` reads one with our own code, from its file through a `Window` (nothing past the checked size): the end record, which must end the file (a classic one, or a zip64 one exactly where the writer puts it; no other end record is ever read; the entry count and the central directory's size refused there against the limits), then the central directory walked record by record (`walk_directory`: exactly the declared count, filling exactly the declared size, each name compared as bytes at once and never kept (a media name parsed into its hash and kind, `Role::Media`; media names twice found by sorting them by hash, `media_by_hash`), zip64 sizes from the extra field; a media entry empty or declaring more than its kind's limit refused there), then each entry's local header (`Entry`: role, method, CRC, declared size, the bytes it takes), and entries that do not overlap and end before the directory. `open_entry` streams an entry's data (Stored, or Deflate through `flate2`) with a hard cap, its SHA-256, and its CRC and size checked at its end, failing as soon as it gives more than it declares (`EntryReader`, ADR 0063); `copy_entry` streams one to a writer, for the media import. `media_entries` / `media_entry` give the media entries in hash order. `Window` reads past a forward seek of at most 32 KiB instead of seeking, so a buffered reader keeps its buffer over many small entries. `Archive::open_anki` reads an Anki package's layout instead (`Layout::Anki`, `AnkiName`): Anki's names each once (other names passed over, never read), at least one collection, numbered media files by number (`anki_entry`, `anki_file`).
  - `source.rs`: `Source` (the user's file, or bytes in tests), opened again by each pass; only a regular file (`NotAFile` otherwise); its `Stamp` (size, modification time, device, inode).
  - `stream.rs`: `cards.json` as a stream: a serde visitor over the top-level object and each list, handing each record (parsed with its `format` type) to a `Sink` and dropping it, with a `Focus` (everything in one pass, the shape only, or one list); `Header` read alone; the reader under serde_json (`JsonInput`) refuses a string longer than any field can be (`string_limit`, six times the longest text limit) and nesting deeper than `MAX_DEPTH` (1,024); `ReadEnd` says what one read found, in the order the checks come (the archive, a string too long, the JSON).
  - `validate.rs`: the checks of one row that need no other row and no database, one function per table (`deck_fields`, `card_fields`, `tag_fields`, `event_fields`), in the order the checks have always run, and `check_id`, the top level and the settings.
  - `media.rs`: the media of an import (ADR 0054): `MediaList`, the `media` records checked as they stream by (`validate::media_fields`: hash, sorted and once, type, size, time) with a 56-byte note each, at most as many as the archive has media entries; `check_entries` pairs records and entries by hash (names, sizes); `check_contents`, in the plan, reads every media entry once without writing it (its first bytes of the record's type, an audio entry kept whole, at most 20 MB, and plain audio by `check_structure`, its SHA-256 the record's hash); `store_new_media`, in the apply's transaction, streams each new file into the media folder through a `media::MediaBatch` and inserts its row.
  - `notes.rs`: what the import keeps of the rows read (`Notes`): ids as values in vectors sorted once their table is read, name keys as 64-bit digests, 32 bytes per log entry (`EventNote`) and per undo (`UndoNote`); `seal` sorts a table's notes and returns the values seen twice (`Candidates`), which `Locate` confirms on a second read of the table, row by row, in memory fixed by the number of candidates (a flag per id, a 128-bit hash per name digest).
  - `engine.rs`: `Engine`, the `Sink` of a plan or an apply: each row checked (with the notes for uniqueness, references and undo targets), compared with the database by id (new, present, revived or a conflict; tags mapped by name key; the cards deleted with a revived deck after the cards; deck name conflicts listed last), each decision added to a SHA-256 digest, and, applying, written at once (undos after the whole log, in id order); `classify_media` compares each media record with the `media` table by hash (new, present, or `Conflict::MediaDiffers`) after the lists. `Stop` says why it stopped a read (read again step by step, a problem, candidates to confirm, a stale plan, the database).
  - `import.rs`: `Store::plan_import` (reads in one pass a file as an export writes it, else step by step in the order of the checks: the version alone, the shape, the top level, each list, the settings, with an engine that only checks (`checks_only`), then each list again compared with the database; no writes) and `Store::apply_import` (no-op if nothing is new or revived; else the same stamp, a backup, then one transaction that reads the file again the same way and writes row by row, refused with `ImportPlanStale` if a decision differs from the plan's and `ImportFileChanged` if the file did; then the settings when the plan applies them and the schedules of cards with new entries via `storage::rebuild_cards`). `compare` is the merge rule of a deck or card whose id the database has.
  - `export.rs`: `Store::export_to` (atomic write, mode `0600`, the archive written straight into the temporary file) and `export_bytes_at` (tests), reading every table, the stored settings and the media rows in one read transaction, sorted by id (media by hash); each media file is checked (a regular file of the recorded size, kind and hash), left out with its record and counted if it is missing or damaged, and streamed from the media folder into the archive, hashed again.
  - `anki/`: the Anki import (ADR 0061). `mod.rs`: the public types (`AnkiPlan`, `AnkiSummary`, `AnkiReport`, `AnkiFormat`, `Skip` (each reason something is left out or changed, in report order) with `Skipped` (count and examples), `AnkiProblem` for a refused package, `FileKind`, `ANKI_EXTENSIONS`). `package.rs`: the package (`Package`: the version from `meta`, the media list from JSON or protobuf, `extract_collection` into a `TempCollection` in the data directory (removed on drop; `remove_stale_temps`), `DataReader`: an entry decompressed by the zip reader and, in the current format, by `ruzstd`, capped, checked whole at its end) and `AnkiLimits`. `proto.rs`: a protobuf reader of varints and length-delimited fields. `json.rs`: the legacy JSON (note types, decks, the media list) read with bounded serde visitors (counts, string lengths, everything else skipped). `collection.rs`: the collection opened read-only and defensively, with a progress handler that stops any statement once the import is cancelled (the flag copied from the caller's by `import.rs`'s `interruptible`, ADR 0063), lowered SQLite limits, a schema with virtual or shadow tables or generated columns refused before anything is read (`check_schema`), values measured with `octet_length` (`Collection`: note types and decks from JSON (schema 11) or tables (15–18), `each_card` walking cards with their notes in id order and their log entries merged in, values measured in SQL before they are fetched). `template.rs`: Anki's templates (`Template`, `CardFields` prepared once per card, `CardContext`, sections, special fields, filters, an output cap and a work budget, `after_answer_rule`). `cloze.rs`: clozes for card *n*. `html.rs`: the tokenizer (`entities.rs`, HTML's named references, generated by `make_entities.py`), the tree, and its conversion into `markdown.rs`'s `Block`s and `Inl`s through a `Resolver` (media names, remote images, math); `markdown.rs` writes them escaped, with emphasis only where it parses back. `convert.rs`: one card's two sides (`card_sides`), the `Report`, `math_drawable` (Rappel's parser and `ratex-parser`). `import.rs`: `Store::plan_anki_import` and `Store::apply_anki_import` (a `Run` reads the package, checks the media notes name, then a `Walk` converts each card, compares it with the live cards (deck, front, back), counts or writes it through a `Writer`, and digests every decision; the apply stores the used media, rebuilds the schedules via `storage::rebuild_cards`, and commits), `history` (the log mapping) and `rappel_deck_name`. `tests/`: `fixtures.rs` (the packages Anki made, in `fixtures/` with `make_fixtures.py` and its README: every format gives the same cards, the counts and the report, conversions, media, history and schedule, tags, re-import, merging decks, cancel, a stale plan, a changed file, `file_kind`), `convert.rs` (HTML to Markdown, escapes read back, a random round trip), `review.rs` (the review's attacks and cases: bounded JSON, values not loaded, virtual tables and generated columns, template work, cancel, the plan's clock, filtered and forgotten reviews, the zstd checksum, media numbering, decks renamed since the plan, NULL columns, names with `:`), `hostile.rs` (packages built by `builder.rs`: bombs, limits, broken and hostile SQLite, templates, HTML, fields, log times, deck and media names, 20,000 cards in a time bound).
  - `tests/`: `mod.rs` holds the shared fixture and helpers; `format.rs` (a fixed fixture that pins the format), `round_trip.rs`, `revive.rs` (merges, reviving deleted rows), `conflicts.rs`, `concurrent.rs` (the second connection: an export beside an open write, an import beside an open reader, a plan made stale by the main store, the worker types being `Send`), `refused.rs` (malformed and tampered files, special files), `fuzz.rs` (lying zip headers, damaged and random bytes, zip tricks, random and damaged JSON: refused or harmless, within a time bound, never quoting the file), `property.rs` (random databases), `large.rs` (larger data; the pre-rename `.cards` export is refused by its version), `settings.rs` (settings in the export, applied or kept), `log_and_tags.rs` (version 2's entries and tags: refusals, conflicts, merges), `suspended.rs` (the `suspended` flag in the file and the search index of imported cards), `streaming.rs` (property tests against the old reader for random damaged files in any key order and damaged text, and the old apply on a copy of the database for the accepted ones; key order, logs in any order, colliding name digests, a file changed between plan and apply or between two reads of one plan (`import::BEFORE_READ`, a test hook), strings too long, hostile records), `limits.rs` (every limit at its boundary and one past, planned and applied, ADR 0063), `zip_attacks.rs` (deflate bombs, zip64 extremes, local headers that disagree, odd names, an exactly 2 GiB sparse archive in `target/tmp`, a file cut or swapped for a pipe after the plan; long comments behind a lying directory size, many end records, a hidden zip64 end record, a directory with more than its records: refused quickly; media names with paths, `..`, upper-case hex or other extensions, a media file twice, media entries stored wrongly, a media bomb, a wrong hash, 20,000 media entries), `media.rs` (media in the export and the import: entries and records, a byte-for-byte round trip, missing and damaged files, conflicts, each refusal writing nothing, a file changed between plan and apply), `archive_reader.rs` (entries, a capped and hashed copy, zip64, limits refused from the end record, a sparse file over 2 GiB), and `oracle.rs`, the reader of the whole document the import had before ADR 0053, kept only to compare with. `tests/fixtures/export-v1.cards` is the pre-rename export `large.rs` reads.
- `src/storage/`: SQLite storage (ADR 0005).
  - `mod.rs`: `Store::open_concurrent(data_dir)` opens a second connection to a database `Store::open` already opened, for a worker thread: it never creates the file, runs no check, backup or migration, and refuses a schema that is not the latest (ADR 0018). `Store::open(data_dir)` opens `<data_dir>/rappel.sqlite3` in named steps: `connect`, the integrity and version checks, `apply_write_settings` (WAL, `synchronous=FULL`, foreign keys), `back_up`, the migrations, `recover_trashed_rows` (the media trash's files the database has rows for come back, ADR 0057; `open_unchecked` ends here), then `checked`: the stored settings are read, so a damaged one stops the open as `Error::DamagedSetting` naming its `SettingKey` (ADR 0052). A failed daily backup or prune does not stop it. It is kept as an `OpenWarning` for `take_open_warnings`. `Store` owns the connection, an `IdGen`, its backup directory and its media folder (both `None` for in-memory test stores; `interchange` uses the first to back up before an import, `media` the second, ADR 0054). `observe_max_id` raises the generator above a table's largest id before each write that issues one.

### `rappel` today

Pages live in `src/pages/`, dialogs in `src/dialogs/`, reusable widgets in `src/widgets/`, and helpers shared by all of them in `src/ui/`. Each page, dialog and widget with a layout has it in a `data/*.blp` file named after it; the pure decisions of a screen (texts, counts, keys, focus targets) are in a `text.rs` (or `layout.rs`, `keys.rs`, `field.rs`) beside it and are unit-tested without GTK.

- `history_row.rs`: `HistoryRow` (`data/history_row.blp`), one entry of a card's history.
- `backup_row.rs`: `BackupRow` (`data/backup_row.blp`), an `AdwActionRow` with a backup's time and size and a Restore button, which the recovery page connects.

**`src/render/`**: a `Document` → GTK widgets, with libadwaita style classes only (ADR 0019). The one place where widgets are built from data in Rust.

- `mod.rs`: `render(doc, images)`, a vertical box with one widget per block (at most 2,000 widgets, then plain text); `Images` says where a side's images come from (the media folder) and their height cap. A paragraph with `media:` images or audio links at its top level is its runs of text, its images and its audio controls one under the other (`paragraph`, `image_widget`, `audio_widget`; at most 20 images and 20 audio controls per side, ADR 0055, 0056). `audio_controls` lists the audio controls under a widget (R on the review page); `stop_audio` stops the one playing. Labels are wrapping, not selectable, so the focus stays on the review page. `fill` / `clear` replace or empty a box's rendered content (review page and editor preview). `shown_part` keeps at most `MAX_SHOWN_BYTES` (32 KiB) of a side, cut after a paragraph, for both of them: Pango's first layout of a longer paragraph freezes the window (ADR 0025). Links show their URL as a tooltip (`query-tooltip` → Pango layout index).
- `breaks.rs`: `Runs` / `breakable` give every label's text a zero-width space after each 64 characters without a breaking space, only between grapheme clusters (`unicode-segmentation`), because a wrapping label's first measure grows with the square of its longest unbroken run (ADR 0025). The markup counts runs across tags. `without_breaks` takes them out again for screen readers: `accessible_text` of math paragraphs, and the accessible name of every label that has them (`render::name_without_breaks`, ADR 0051).
- `markup.rs`: `inline_markup(inlines, budget)`, inlines → Pango markup with every piece of card text escaped and only our own tags (no `<a>`; a `media:` image where it cannot be a picture is its alt text in italics, and an audio link where it cannot be a control its words in italics, or "Audio"), plus each link's byte range and each drawn formula's placeholder (U+FFFC) index; `link_at`. Pure and unit-tested (Pango parses every result).
- `math.rs`: LaTeX → RaTeX display list, pure (ADR 0021, 0023). `lay_out` (source over 4 KiB is not parsed, a layout over `MAX_EM` = 128 em or RaTeX's own limit is `TooLarge`, a panic inside RaTeX is a parse failure), the bounded `formula` cache (800 entries, keyed by source, style and colour), `Budget::place` (at most 200 formulas per side: `Formula`, `ErrorSource` or `Source`), and the font-size and pixel helpers. Unit-tested with the spike's formulas, invalid and hostile input.
- `math_view.rs`: `MathView`, one formula drawn with `Snapshot::append_cairo` and `ratex_cairo`, in the widget's CSS `color` (live on a theme switch). Accessible role Math, label the LaTeX source. Not focusable.
- `math_paragraph.rs`: `MathParagraph`, text with formulas in it: Pango lays the text out with an `AttrShape` box per formula so each sits on the text baseline; each formula is a `MathView` in a horizontal scroller without a scrollbar (`render::inline_math_scroller`, ADR 0024) put where Pango put its box, as wide as the formula and never wider than the line. Used for paragraphs, headings and table cells that have a drawn formula; others stay `GtkLabel`s.
- `images.rs`: the image decisions, pure (ADR 0055): `pieces` (a paragraph's text runs, `media:` images and `media:` audio links; any other target stays text and is never read), `image_count`, `audio_count`, `display_size` (scaled down to the width and a height cap, never up), `max_height` (60 % of the view, at least 120 px), `within_limits` (16,384 px a side, 64 MP), `accepted_mime` (glycin's reading of the type must match the kind: no SVG), `Failure` with the placeholder texts and `image_name`, `ImageBudget` (20 per side), `PixelBudget` (64 MP per side), `TextureCache` (least recently used, 256 MiB and 256 entries) and `read_image_file` (`media_file::read_media_file` for an image kind, its header's size within the limits by `media::image_size`, without its colour profile by `media::without_color_profile`, so neither a huge claim nor a profile reaches glycin; ADR 0063).
- `media_file.rs`: the one checked read of a media file (ADR 0055, 0056): `read_media_file` (a regular file of the media folder opened with `O_NOFOLLOW | O_NONBLOCK` and checked on the handle, within its kind's limit, of its kind by its first bytes, an audio file plain audio over its whole length by `check_structure`, read whole for the decoder) `read_audio_for_playing` (the same, cut to `audio_payload`: an MP3's frames only, ADR 0062) and `check_media_file` (the same checks on its first bytes only, for whether an audio control is available); `Unreadable` (missing or refused).
- `audio.rs`: the audio decisions, pure (ADR 0056): `link_text` (the link's words on one line), `button_text`, `State` (Ready, Loading, Playing, Unavailable, TooMany, Failed, with its icon, tooltip and note), `accessible_label` ("Play audio: …"), `time_text` ("0:03 / 0:12"), `AudioBudget` (20 per side).
- `playback.rs`: `available`, whether GStreamer's `libgstplayback.so` (playbin3) is where GStreamer looks for plugins (`plugin_dirs`, `playback_found`, `library_dir_from_maps`, pure and tested), checked once before any `GtkMediaFile` is made, since `GstPlay` aborts the process without it (ADR 0056).
- `audio_player.rs`: `CardAudio`, one `media:` audio link (ADR 0056): a button (icon and words; not focused by a click) and a dimmed note (the time, or why it cannot play). The file is looked at when rendered (`check_media_file`, on a worker), read only on a press or R (`read_audio_for_playing`, on a worker) and played as a memory stream by `gtk::MediaFile` (GTK's GStreamer backend; never a URI); one plays at a time (`stop_all`), it stops when unmapped, nothing is read or played when `playback::available` says no, a stream with a picture track or not prepared within `PREPARE_TIMEOUT` (10 s) fails, and a stream let go of before it is prepared is kept until it is (`retire`, a GTK 4.24 quirk).
- `picture.rs`: `CardImage`, one `media:` image (ADR 0055): decoded by glycin in its sandboxed loader process from the checked bytes, on the main loop without blocking it (`decode`, a 10 s timeout that is not cached; a warning once if glycin runs unsandboxed), cached by path, within the side's pixel budget, then a flat button (`card-image` in `data/style.css`, its rounded corners clipping the picture; named by the alt text, not focused by a click) whose `measure` is `display_size`, or a dimmed placeholder (one Img for screen readers). A click, Enter or Space opens `data/image_dialog.blp` (`full_size_layout`), the image scaled down to fit.
- `style.rs`: the pure decisions: `back_shown`, `heading_class`, `list_marker`, `table_cell_classes` (borders and header row of a table cell), `widget_cost` (with what a side's images and audio controls add). Every side is laid out the same way. Unit-tested.

**`src/transfer/`**: Export… and Import… from the primary menu (ADR 0018), Anki packages included (ADR 0061).

- `mod.rs`: the `GtkFileDialog`s (Import… offers Rappel exports and Anki packages together, or each kind alone), the workers (`ui::worker`), the import dialog (`data/import_dialog.blp`, `confirm_layout`: Import Data? / Cannot Import / Nothing to Import) and the toasts. A chosen file that is an Anki package (`AppState::file_kind_on_worker`) goes to `anki.rs`.
- `anki.rs`: the Anki import: the package read on a worker behind a toast with Cancel (`progress_toast`, an `Arc<AtomicBool>`), "Import from Anki?" with the report in the import dialog's label, the import on a worker behind another such toast, then "Import done" with the report behind Details (`ui::toast::report_toast`: the lines left-aligned below the summary).
- `anki_text.rs`: its texts (`anki_view`, `report_text`: Left out / Changed, a line per reason with plural forms and examples in quotes; `anki_imported_text`, `anki_refused_text`, the progress toasts). Pure and unit-tested.

Pure and unit-tested.

## UI build pipeline

UI layout is written in Blueprint, never in Rust code or hand-written `.ui` XML.

```
data/*.blp ──blueprint-compiler──▶ $OUT_DIR/ui/*.ui ──glib-compile-resources──▶ $OUT_DIR/rappel.gresource
                                                                                  │
                                         gio::resources_register_include! ◀───────┘ (embedded in the binary)
```

`crates/app/build.rs` drives both steps; `data/resources.gresource.xml` lists the files under the resource prefix `/io/github/rsmirke/Rappel/`. Widgets load their template with `#[template(resource = "/io/github/rsmirke/Rappel/<name>.ui")]`.

`build.rs` also compiles each language of `po/LINGUAS` (the repository's `po/` folder: `LINGUAS`, `POTFILES.in`, `rappel.pot`, `<lang>.po`) into `$OUT_DIR/locale/<lang>/LC_MESSAGES/rappel.mo` with `i18n/po.rs`, rerunning when `po/` changes; a debug build reads its translations from there (ADR 0059). Strings in `.blp` files are marked `_("…")` or `C_("context", "…")`; `GtkBuilder` looks them up in the default domain.

`build.rs` runs both tools itself (no `glib-build-tools`). It tells Cargo to run it again when `data/` (as a directory, so a new or removed file counts), any `data/*.blp`, `data/resources.gresource.xml` or a file the manifest bundles from `data/` (`style.css`) changes; the `.ui` files it writes to `OUT_DIR` are not listed, so one edit costs one build. The crate is then compiled again because `gio::resources_register_include!` includes the gresource with `include_bytes!`. Cargo goes by modification times, so a file copied in with an older time is missed (`cargo clean -p rappel`, README); `ui_files.rs` catches the mismatch in the gate (ADR 0047).

Files of two kinds live in `data/`: composite templates (a `template` block, loaded by `#[template]` when the widget is built) and plain layouts that `ui::dialog::builder` loads (alert dialogs, Preferences, Card Information, the shortcuts dialog). Each plain layout is loaded by one function next to the code that uses it (`card_info::Layout::load`, `browser_dialogs::choose_layout`, `transfer::confirm_layout`, …) or, for an alert that is the only object of its file, by a named `ui::dialog::Alert` constant (`DELETE_CARD`, `DISCARD_CHANGES`, `RESTORE_BACKUP`, `START_FRESH`). `src/ui_files.rs` (tests only) lists every `data/*.blp` file with how it is loaded and checks that each is in the gresource and loads: a template widget is built, which runs gtk4-rs's checks of its `#[template_child]` ids and types (a mismatch aborts the test binary with the id in its message), and a plain layout goes through its loader, which logs each object it looks up that is missing or of another type and returns `Err` with the first one's id, which the test names. A `.blp` file with no entry fails the test.

## Desktop integration drafts

The top-level `data/` folder (not `crates/app/data/`, which is compiled into the binary) holds what packaging will install (ADR 0060): `io.github.rsmirke.Rappel.desktop.in`, `io.github.rsmirke.Rappel.metainfo.xml.in` (description, releases, content rating, screenshots by URL), placeholder icons in `icons/hicolor/{scalable,symbolic}/apps/`, and the committed store screenshots in `screenshots/`. Nothing builds or installs them yet (packaging is phase 3); their translatable texts are in `po/POTFILES.in` and `po/rappel.pot`. `crates/app/src/desktop_files.rs` (tests only) runs `desktop-file-validate` and `appstreamcli validate --no-net --pedantic` on them in English and with French merged in, and checks that the ids, binary, icon name, gettext domain, licence and links are the code's, that the releases are `CHANGELOG.md`'s versions, that the screenshots are committed PNGs within Flathub's size, and that the icons are plain SVG. `fill_scratch_db --demo` makes the data the screenshots show.

## Quality gate

`scripts/check.sh` runs `cargo fmt --all --check`, `cargo clippy --workspace --all-targets --locked -- -D warnings` (with `clippy::pedantic`, `unwrap_used`, `expect_used`, and `allow_attributes` / `allow_attributes_without_reason`: a lint is silenced only by `#[expect(.., reason = "..")]`, which fails the build once it is no longer needed), `cargo test --workspace --locked` and `cargo deny --locked check -D license-exception-not-encountered` (licences compatible with GPL-3.0-or-later, RustSec advisories, crates.io only; the `-D` makes an unused licence exception an error, so a changed `OFL.txt` hash for the KaTeX fonts cannot pass silently, ADR 0023). `third_party/` (vendored code, ADR 0021) is a workspace `exclude`, so none of these steps checks it. `scripts/screenshot.py` (batch mode only, run with `python3 -I`; `--env` passes e.g. a French locale, `--decoration-layout :close` shows GNOME's window buttons) starts the app on a private Xvfb display (a free number Xvfb picks itself, with a fresh authorization cookie) with a copied or new scratch database, a given size and colour scheme, and a home folder of its own; it sends keys and clicks only through XTest on that display (the app gets no session bus or AT-SPI), cleans up on every exit, and refuses real data folders, and saves screenshots to the git-ignored `docs/briefs/screenshots/`; its `resize:W,H` step resizes the app's window as an on-screen keyboard does (ADR 0058). `scripts/pre-commit.sh` refuses commits on `main` and then runs the gate; `scripts/install-hooks.sh` installs it. `.github/workflows/ci.yml` runs the same `scripts/check.sh`, under Xvfb (`xvfb-run -a`), on every pull request and on pushes to `main`, in an `ubuntu:26.04` container with the README's system packages and stable Rust (see ADR 0003). Some tests start GTK, so the gate needs a display (ADR 0024). They go through `crates/app/src/testing.rs` (test builds only): one thread owns GLib's default main context and runs their bodies one at a time, because `gtk::init` keeps that context for good. `testing::with_gtk` runs a body there with GTK started (`on_main_context` without it); `testing::with_widgets` also starts libadwaita and registers the app's resources (once per run), for tests that build its widgets or load its `.ui` files: every such test goes through it, none calls `adw::init` or `resources_register_include!` itself; `testing::thread_cpu_time` and `cpu_time_of` read the thread's CPU time, and `testing::assert_cpu_within` / `cpu_within` check it against a bound at the speed of the machine the bounds were set on (`slowdown`, through the pure `judge`), so time bounds hold under load (ADR 0049); call them on the thread that did the work; `testing::settle_until` runs the main context until a condition holds or a timeout passes (waiting on GTK, not timing). `testing::run_alone` runs one test alone in a new process of the test binary with a configured environment and fails unless it passed (fresh GTK types, GStreamer's variables, a locale, an abort). `testing::temporary_state` opens a new database in a temporary directory, and `testing::png_bytes` encodes a real PNG with GDK, and `testing::wav_bytes` writes a WAV of silence. `testing::within` (and `within_stack`, with a stack size of its own) runs a test's work on `SMALL_STACK` with a CPU-time bound and a separate wall-clock hang timeout (`hang_limit`), as `rappel-core`'s `test_support::within` does; `RAPPEL_TIMINGS=1` makes them and `print_timing` print the times.

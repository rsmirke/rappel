# 56. Audio: checked as plain audio, played by GTK's GStreamer media stream, never on its own

- Status: Accepted
- Date: 2026-10-18
- Amends: ADR 0054 (the `[audio: …]` placeholder is gone; `Store::add_audio`, `MediaProblem::NotAudio`; an audio file is accepted by the store, the import and the export only if all of it is plain audio of its kind, `MediaProblem::Malformed`), ADR 0055 (the editor's Insert Image… path, paste and drop take audio files too; one checked read of a media file for images and audio), ADR 0025 and ADR 0050 (rows 46 to 49 of the untrusted-input table), ADR 0039 (R on the review page, in the Keyboard Shortcuts dialog)
- Refers to: SPEC §4.9, §4.3, principle 5; `docs/briefs/phase-2.md` (slice 4)

## Context

Slice 2 (ADR 0054) gave the media store and `Inline::Audio`, a link `[words](media:<sha256>.<ext>)` to an Ogg (Opus or Vorbis), MP3, M4A or WAV file of at most 20 MB; the app showed `[audio: …]`. This slice plays it: a play control on the card, never autoplay, R on the review page plays the card's audio again, and Insert Audio… and drag and drop in the editor. No recording. SPEC §4.9 says playback is by GStreamer, opens only a local file built from the hash, never a URI from card text, with an allow-list of formats and decoders, and asks the ADR to justify the GStreamer binding as a new dependency.

Audio demuxers and decoders are an attack surface like image decoders, and the files come from imports and drops.

## Decision

### 1. Playback: `GtkMediaFile`, no new dependency

GTK 4.24 has GStreamer playback built in: `libgtk-4.so.1` links `libgstplay-1.0`, `libgstreamer-1.0` and `libgstaudio-1.0`, and its `GtkMediaFile` implementation for GStreamer (`GtkGstMediaFile`) plays a stream with `GstPlay` (playbin3). **No GStreamer Rust binding is added**: `gtk::MediaFile` and the `MediaStream` interface of gtk4-rs (already a dependency) play the files; the cost is that decoders cannot be allow-listed (§1a).

**How a file reaches GStreamer** (`render/media_file.rs`, `render/audio_player.rs`):

1. Only an `Inline::Audio` is ever played: a checked hash and an audio kind; the path is the media folder joined with the name the core builds (`MediaRef::file_name`). A link to anything else (`https:`, `file:`, a path, a bad hash) is an ordinary link, never a control (a unit test lists them).
2. **Nothing is read until the user asks.** When a side is rendered, the file is only looked at, on a worker thread (`check_media_file`: opened with `O_NOFOLLOW | O_NONBLOCK`, a regular file on the handle, not empty, within 20 MB, its first bytes of the reference's kind), so a missing or wrong file shows at once as "Audio not available". No byte goes to GStreamer.
3. On play (a click, Enter or Space on the focused button, or R), `read_media_file` reads the whole file on a worker thread with the same checks on the open handle, read capped at the limit plus one byte, and its first bytes of its kind again. The function is shared with images (`images::read_image_file` is it plus "an image kind"), the one way the renderer reads a media file.
4. **The whole file must be plain audio of its kind** (`rappel_core::media::check_structure`, §1a below), checked again on the bytes read, so a file stored before the check existed, or put in the folder by hand, is refused here ("Audio not available") before a byte reaches GStreamer.
5. Those bytes go to `gtk::MediaFile::for_input_stream` over a `GMemoryInputStream`. GTK hands GStreamer the stream through a source element it sets up itself (`source-setup`; GTK 4.24's library names `giostreamsrc`, and GStreamer's error messages show the stream entering through `urisourcebin`), not a file URI: **no `file:` or other URI of ours ever reaches playbin**, and the file cannot change between the check and the play.
6. A stream GStreamer finds a picture track in (`has_video` once prepared) is stopped and the control says "Could not be played": an audio kind by its first bytes that GStreamer takes for a video is not card audio.
7. A stream not prepared within `PREPARE_TIMEOUT` (10 s) is given up the same way. An error (`GtkMediaStream:error`) is logged at debug level, never with card text, and the control shows its failed state; pressing it again tries again.

### 1a. The first bytes are not enough: the structure of the whole file

**Found in review and reproduced** (GStreamer 1.28, `strace`): a file whose first bytes are an ID3v2 tag is an "MP3" by `MediaKind::detect`, yet GStreamer drops the tag, finds the format of what follows itself, and plays an **HLS master playlist** there with `hlsdemux2`, which **opened the variant playlist and the segment it named** (`file:///…`; an `http(s):` URI would go through `souphttpsrc` or `curlhttpsrc`, the network). DASH (`dashdemux2`), Smooth Streaming (`mssdemux2`) and SDP sessions (`sdpdemux`, which opens UDP sockets) are installed here too. The memory stream does not help: the URI is inside the content. That broke "no network, ever" (principle 5) for a file a card or an import brings.

**Fixed in two layers.**

1. **Plain audio only, everywhere a file comes in** (`media/structure.rs`, `check_structure(kind, whole file)`, pure, one pass, never panics):
   - **MP3**: ID3v2 tags (their declared syncsafe sizes, the v2.4 footer), then MPEG audio layer III frame headers with valid version, bit rate (no free format) and sample rate, each frame whole, back to back to the end; at the end an optional APE tag (version 1 or 2, as MP3Gain writes ReplayGain) whose items exactly fill the size its footer declares, as many as it says, each a value size, flags, a key of 2 to 255 printable ASCII characters ended by a NUL, and a value within the tag, with its header where the flags announce one; an item of type locator (flag bits 1 and 2 equal to 2, a link to something elsewhere) is refused, and no other item is acted on, then an optional ID3v1 tag (Xing, Info and VBRI headers live inside the first frame, so they pass). Anything else, a cut last frame included, is refused.
   - **Ogg**: every page (`OggS`, version 0, known flags, segment table, its CRC), one logical stream (one serial number, the first page the only one beginning a stream, page numbers in order, nothing after the last page), the first packet `OpusHead` or `\x01vorbis`. Chained or multiplexed streams and trailing bytes are refused.
   - **WAV**: a RIFF `WAVE` chunk exactly as long as the file, its chunks within it (pad bytes counted), one `fmt ` of PCM (1) or IEEE float (3), or `WAVE_FORMAT_EXTENSIBLE` with those sub-formats, before one `data` chunk; other chunks are skipped, not interpreted.
   - **M4A**: boxes within their parents to the end of the file (64-bit sizes, size 0 to the parent's end, at most 16 deep), `ftyp` first with an audio brand, one `moov`, and `mdat`. **An allow-list, not a deny-list** (found in re-review: qtdemux decompresses a compressed movie, `cmov` with `dcom` and `cmvd`, and parses it, so a redirect, a reference movie, an external data reference or another track could hide inside one, and a deny-list walk did not look there). Only these boxes are accepted, anything else there refuses the file:
     - top level: `ftyp`, `moov`, `mdat`, `free`, `skip`, `wide`, `uuid` and `pdin` (not walked);
     - `moov`: `mvhd`, `trak`, `udta`, `meta` (GPAC writes it here), `iods`, `uuid` (not walked), `free`, `skip`;
     - `trak`: `tkhd`, `edts`, `mdia`, `udta`, `free`, `skip`; `edts`: `elst`;
     - `mdia`: `mdhd`, `hdlr` (must be `soun`), `minf`, `free`, `skip`;
     - `minf`: `smhd`, `hdlr` (a QuickTime data handler), `dinf`, `stbl`, `free`, `skip`; `dinf`: `dref`, whose every entry is a `url ` or `urn ` with flag 1 (the data is in this file);
     - `stbl`: `stsd`, `stts`, `stsc`, `stsz`, `stz2`, `stco`, `co64`, `stss`, `sgpd`, `sbgp`, `free`, `skip`; `stsd`'s entries only `mp4a`, `alac` or `Opus` (sound description version 0, 1, or 2 with its fixed structure, whose size field at +28 must read 72), with only `esds`, `alac`, `dOps`, `btrt`, `chan`, `free` inside, and in a version 1 or 2 entry a QuickTime `wave` box holding only `frma`, a small `mp4a` atom, `esds`, `chan` and the terminator. Every `esds` (here or in `wave`) has an `ES_Descriptor` without the URL flag (a URL would name the stream elsewhere) and a decoder configuration whose object type is audio: 0x40 (MPEG-4 audio), 0x66 to 0x68 (MPEG-2 AAC) or 0x6B (MPEG-1 audio);
     - `udta` (in `moov` or a track): any box but the refused ones below, none walked into: qtdemux reads only the tag entries it knows there, and looks for redirects and compressed movies only directly in `moov`;
     - `moov/meta`: `hdlr`, `ilst` (the tags, not walked), `keys`, `free`, `skip`; an ISO full box (version and flags first), or a QuickTime one without them (Apple's `mdta` tags, as an iPhone writes them), told apart by the handler's type where its first child would be.
     So `cmov`, `dcom`, `cmvd`, the reference-movie and redirect boxes (`rmra`, `rdrf`, `rmda`, `rmdr`, `rmvc`, `rmcd`, `rmqu`, `rmcs`; named in their own error), fragmented movies (`mvex`, `moof`), track references and video or text sample descriptions are all refused. The list is what real encoders write (FDK AAC with `mp4mux`, ffmpeg, GPAC, Apple's tools, iTunes tags with cover art; tested with built copies of each layout). **Real files still refused**, accepted costs: fragmented MP4 audio (`moof`, as DASH and some streaming encoders write); M4B audiobooks with chapters as a QuickTime text track (`tref/chap` and a `text`/`tx3g` track): GStreamer would expose that track as a subtitle stream, the track references and text sample descriptions would need allow-lists of their own, and refusing the whole file keeps the rule "every track is sound" simple (the Nero-style `udta/chpl` chapter list passes, as a `udta` leaf); files with other boxes than those above (a QuickTime `wave` in a version 0 description, `ctts` or `sdtp` in an audio sample table, unknown vendor boxes outside `udta` and `uuid`), and MP3 files with a cut last frame or junk between frames. Each is said in words: a damaged file as "This audio file is damaged", a whole one with more than plain audio as "This audio file holds more than plain audio, so Rappel does not take it". **`GstPlay` follows a redirect message (a new location), and `filesrc` cannot be demoted (layer 2), so for M4A "never a URI" rests on this check.**
   It runs in `copy_capped`, so in `Store::add_media`, `add_audio` and the import's apply (an audio file is kept in memory while copied, at most 20 MB), in the import's plan (`check_contents` keeps an audio entry whole, at most 20 MB, one at a time: a refused file is `NotOfItsType` before anything is written), in the export (a stored audio file that fails is left out as damaged and counted), and in `read_media_file` before playing. A file refused is `MediaProblem::Malformed` (damage: cut, out of bounds, bad checksums, junk where audio should be) or `MediaProblem::NotPlainAudio` (a whole file holding more: another stream, a reference, a box or a format audio files do not have); `check_structure`'s `Malformed { why, extra }` says which, and the tests check each reason. Real files made by GStreamer's encoders (LAME, Opus, Vorbis, FDK AAC with `mp4mux`, `wavenc`) pass; they are the test fixtures (`media/fixtures/`, whose README has the exact commands; the M4A's major brand set to `M4A `, as Apple's tools write it).
2. **Defence in depth: GStreamer's URI-following and network elements are demoted** (`gst_env.rs`). GStreamer reads `GST_PLUGIN_FEATURE_RANK` at `gst_init` (exact feature names, later entries winning), and playbin never autoplugs a feature of rank `none`. Rappel gives rank `none` to `hlsdemux`, `hlsdemux2`, `dashdemux`, `dashdemux2`, `mssdemux`, `mssdemux2`, `sdpdemux`, `souphttpsrc`, `curlhttpsrc`, `neonhttpsrc`, `rtspsrc`, `rtmpsrc`, `rtmp2src`, `srtsrc`, `ristsrc`, `rtpsrc`, `udpsrc`, `tcpclientsrc` and `webrtcbin`; GTK's own source for our memory stream is not touched. **Checked**: with these entries the reviewer's playlist no longer opens its variant or segment (`strace` sees no open), and Ogg Opus, Ogg Vorbis, MP3, M4A and WAV still play. Demoting `filesrc` was tried and does not stop `hlsdemux2` (its downloader opens URIs itself), so it is not in the list.
   Setting the environment of a running process is `unsafe` in Rust 2024 (`std::env::set_var`, `glib::setenv`), which the workspace forbids. So the first thing `main` does (after the logger, before GTK, GStreamer or any thread) is, when the variable does not end with Rappel's entries, **start the program again in place** (`execv` through `CommandExt::exec`: the same process, the same arguments and `argv[0]`) with the entries appended after any value the user set. A second variable (`RAPPEL_GST_FEATURES_DEMOTED`) stops a second restart whatever happens to the first; if the restart fails (the binary replaced or removed meanwhile), Rappel logs a warning and carries on with layer 1 only. Checked on the running app: its environment has the user's entry first, then Rappel's. Consequences of the variable: processes Rappel starts (glycin's loaders, a portal helper) inherit it, which is harmless (it only lowers ranks, and none of them plays media through these elements); under a debugger the restart is followed (gdb: "is executing new program"), and setting `GST_PLUGIN_FEATURE_RANK` to a value that already ends with Rappel's entries skips it (README); a Flatpak can set the same value with `--env=` in its finish arguments, so the restart never happens there. The test binary does not restart, so the tests' GStreamer is not demoted (layer 1 is what they check); `gst_env`'s pure function is tested.

**What is guaranteed, and what is not.** Guaranteed: no byte reaches GStreamer unless the user plays it, and then only a file of the media folder that is plain audio of its kind by the structure above, given as a memory stream; no URI of ours reaches playbin; the streaming demuxers and network sources that could follow a URI are never autoplugged in the app. **Not guaranteed: which demuxer and decoder GStreamer chooses for that plain audio.** It picks them itself, by typefinding and rank, and runs them **in Rappel's process**, in GstPlay's streaming threads: on a system with `gstreamer1.0-libav` that can be FFmpeg's decoders. A demuxer or decoder exploit inside a well-formed frame, page, chunk or box (the structure check does not decode) in a file the user then plays runs as the user, inside Rappel. **SPEC §4.9's allow-list of decoders is therefore not met**: formats are allow-listed, decoders are not. A real decoder allow-list needs `gstreamer-rs` (MIT/Apache-2.0, licences already allowed) to veto elements in playbin's `autoplug-select` or build Rappel's own pipeline instead of `GtkMediaFile`, and the GStreamer development packages (`libgstreamer1.0-dev`, `libgstreamer-plugins-base1.0-dev`), which are not installed here and need administrator rights. Pending the maintainer's decision (`docs/briefs/QUESTIONS.md`, Phase 2, question 2).

**Images**: glycin's image-rs loader decodes PNG, JPEG, WebP and GIF from the bytes it is sent, in its sandbox, and never resolves or fetches a URI (none of these formats can name another file); SVG, which can, is refused by its first bytes (ADR 0055). So images need no structure check of this kind.

**What it needs at run time**: GStreamer's `base` plugins (playbin3, Ogg, Vorbis, Opus, typefinding, audio conversion), `good` plugins (WAV, MP4/M4A, MP3 through mpg123, an audio sink) and an AAC decoder for M4A (`fdkaac`, `faad` or `libav`). GNOME systems have them; the README lists them. **Without the base plugins GTK's media stream would abort the process**: `GstPlay` calls `g_error` ("'playbin3' element not found") when the first stream is made, which CI hit (its container had no `gstreamer1.0-plugins-base`; a test that played aborted the whole test binary). So before any `GtkMediaFile` is made, Rappel looks for `libgstplayback.so`, the plugin that provides playbin3, where GStreamer looks (`render/playback.rs`, following `scan_and_update_registry` in `gst/gstregistry.c`: `GST_PLUGIN_PATH_1_0` or `GST_PLUGIN_PATH`, then `GST_PLUGIN_SYSTEM_PATH_1_0` or `GST_PLUGIN_SYSTEM_PATH`, which when set replace the defaults, the user's `$XDG_DATA_HOME/gstreamer-1.0/plugins` and the folder of the loaded `libgstreamer-1.0` plus `gstreamer-1.0`, found in `/proc/self/maps`, then the usual multiarch, `lib64`, `/usr/local` and Flatpak `/app` folders). Not found: every control is disabled and says "Audio playback is not available on this system" (tooltip "GStreamer's base plugins are not installed", also its accessible description), R does nothing, no file is read, and a warning is logged once. A plugin file that is there but cannot be loaded is not caught (a broken installation). Without the good plugins or a decoder, a control says "Could not be played"; nothing else changes.

**Measured**: a truncated WAV, an Ogg whose first page announces Opus followed by garbage pages, an M4A whose boxes lie, HTML under a `.wav` name, and an HLS playlist, a DASH manifest and an SDP session behind an ID3 tag are each refused before GStreamer sees them ("Audio not available") within milliseconds; 20 MB of whole MP3 frames full of noise passes the structure check (it is MP3) and plays, muted in the test, until stopped. The window's thread does not wait on any of them; the structure check of a 20 MB file runs on the worker thread that reads it. **Main-thread time**: making the stream and starting it runs on the main thread (GTK objects live there): about 40 ms the first time in a process (GStreamer's init), and **about 1.7 s once per user and GStreamer update**, when GStreamer builds its plugin registry cache (`~/.cache/gstreamer-1.0`; seen with a fresh home folder, as the screenshot harness and CI have). An accepted cost: it happens on the first play ever, by a user's action.

**A GTK quirk worked around**: closing or dropping a `GtkGstMediaFile` that is not prepared yet, when another stream was made earlier in the process, makes GTK 4.24 call `g_object_unref` on something that is not an object (a GLib critical, found by the tests under `G_DEBUG=fatal-criticals`), and in review `gtk_media_file_clear` (`close`) on such a stream was seen to hang for 60 s. A stream let go of before it is prepared is therefore kept, paused, until it is prepared or fails (or 10 s pass), then dropped from an idle callback (`retire`); do not "simplify" this to `clear()`. Its handlers act only while it is still the control's own stream, so a retired stream cannot change the state of a newer play. A stream still kept when the app quits goes with the process (nothing is written or played after the window closes).

### 2. The control

- **Where.** A `media:` audio link at the top level of a paragraph is a control of its own between the paragraph's runs of text (`images::pieces`, now images and audio), as an image is. Inside emphasis or a link, in a heading or a table cell, it is its words in italics, or "Audio" for a link without words; nothing plays from there (such cards are rare, and a button inside a line of text would need a layout of its own).
- **Looks** (`CardAudio`): a normal button, at the start of the line, with a `media-playback-start-symbolic` icon and the link's words (plain text, wrapping, with the long-run breaks of ADR 0025), "Audio" without words; `media-playback-pause-symbolic` while it plays. Beside it a dimmed caption: "0:03 / 0:12" once GStreamer knows the length (the whole length after the end), "Audio not available" (disabled button, `audio-x-generic-symbolic`), "Audio not available: too many on this side", or "Could not be played" (`dialog-warning-symbolic`, still pressable). A raised button, not flat: it must look pressable in the text. Libadwaita style classes only (`dimmed`, `caption`, `numeric`).
- **Names.** Tooltip "Play" / "Pause" / "Audio not available" / "Audio could not be played". Accessible label "Play audio: <words>" ("Play audio" without words), "Pause audio: …" while playing; the caption's words are the button's accessible description; the caption itself is a Presentation (the ticking time is not read). The card area's own label (`plain_text`) already holds the words. The card lists (`plain_summary`) show the words, or nothing.
- **Clicking**: plays from the start, pauses while playing, resumes a paused play; after the end, from the start again.
- **One at a time**: starting a control stops the one playing and lets go of its stream (and its bytes, up to 20 MB): only one file is in memory.
- **Stops** when the control leaves the screen (`unmap`: the next card, an undo, a suspend or delete, leaving the page, the summary, closing the editor or a preview refresh), and when the review page opens the editor (`render::stop_audio`). It keeps playing when the answer is revealed, and while Card Information is open.
- **Budget**: at most 20 controls per side (`MAX_AUDIO_PER_SIDE`); later ones are disabled and never read. Each costs six widgets in the side's 2,000 (`style::widget_cost`).

### 3. The review page: R

- **R** (and Shift+R) plays the card's audio from its start (`Act::Replay`, never delayed: it grades nothing). Which (`replay_target`, pure): once the answer is shown and the back has audio controls, the first one on the back that can play; otherwise the first one on the front that can play. A side whose controls all cannot play gives nothing: R never plays something other than what is under the eyes. R was free (E, I, S, Delete, 1, 2, Space, Enter, Ctrl+Z are taken).
- **Focus**, as for images (ADR 0055): the button does not take the focus on click (`focus-on-click: false`), so Space and Enter stay the page's; Tab reaches it, and then its own Space and Enter press it (the page's keys run in the bubble phase); 1, 2, E, I, S, R, Delete and Ctrl+Z keep working with it focused.
- The Keyboard Shortcuts dialog lists **Play Audio** (R, "From the start"); its test checks the key table.

### 4. The editor

- **Insert Audio…** (`audio-x-generic-symbolic`, accessible label "Insert Audio in Front" / "in Back") beside Insert Image… in each side's header. A `GtkFileDialog` filtered to the audio MIME types (with the names shared-mime-info gives them: `audio/x-vorbis+ogg`, `audio/x-opus+ogg`, `audio/x-m4a`, `audio/vnd.wave`, …) and the endings `ogg oga opus mp3 m4a wav`; the file's first bytes decide (`Store::add_audio`, new in core: an image is `MediaProblem::NotAudio` before anything is written).
- **Paste and drop** go through slice 3's one path (`dialogs/card_editor/insert.rs`, renamed from `images.rs`): files are added with `Store::add_media`, which takes an image or audio as their first bytes say, so a dropped WAV called `x.png` goes in as audio. Nothing else changes: the drop target's formats are the same (a file list and the four image types; no program offers sound on the clipboard in our kinds), text drops and link pastes behave as before, only local files are read (`AppState::add_media_on_worker`, the `local_path` and regular-file checks of ADR 0055 row 45, for audio too), every read of an offer within 10 s.
- **What is inserted** (`media::insertion`): `[](media:<sha256>.<ext>)` for audio, `![](…)` for an image, each as its kind when several are dropped, one user action, with the cursor between `[` and `]` for the words, consistent with images.
- **Refusals** in words, per what was asked: "This file is not an Ogg, MP3, M4A or WAV audio file", "This audio file is larger than 20 MB", "This file is not an image or audio file of a supported kind" (a drop), and those of ADR 0055.
- The preview plays like the review page; a refresh while typing stops it.

## Consequences

- No new dependency, no migration, no change to the export format. CI installs `gstreamer1.0-plugins-base gstreamer1.0-plugins-good`. Imports are stricter: an archive with an audio file that is not plain audio (a damaged MP3 with a cut last frame included) is refused, and such a file already stored is left out of an export and counted as damaged; such files never played safely anyway.
- Rappel starts itself again once at launch (to demote GStreamer's network elements): the same process, invisible to the user; a launcher sees one process.
- An import plan holds one audio entry in memory at a time (at most 20 MB) while it checks its structure.
- Playback quality and codecs are the system's GStreamer: on a system without an AAC decoder, M4A files "could not be played".
- The first play ever (per user and GStreamer update) holds the window for about 1 to 2 s while GStreamer builds its registry.
- The tests mute every stream they make (`set_muted` in test builds) and accept "could not be played" where a plugin or a sound device is missing. CI installs `gstreamer1.0-plugins-base` and `-good` so they play for real; without the base plugins the tests that play check the "not available" state instead, and a test forces that state (`playback::force`) to check that no stream is ever made then, so a missing plugin can never abort the test binary; that a control reaches GStreamer is checked through a play counter (`CardAudio::plays`, test builds only), not by sound.
- A real allow-list of GStreamer decoders needs `gstreamer-rs` and its development packages: asked in `docs/briefs/QUESTIONS.md` (Phase 2, question 2); until then SPEC §4.9 is met for formats, not for decoders.

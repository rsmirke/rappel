# 50. Untrusted input, round 2

- Status: Accepted
- Date: 2026-10-18
- Amends: ADR 0025 (new entry points, same method), ADR 0026 (rule 4 of backup retention; finishing a restore prunes nothing), ADR 0035 (what a search reads of the query)
- Closes: #50

## Context

ADR 0025 reviewed every place where content Rappel did not write itself comes in, merged at #47. Since then the core gained new ways in: backup retention and restore loose ends (#49), settings (#51), undo, reset, tags and export format 2 (#52), statistics and card information (#59), the search index, suspension and bulk writes (#63), and suspend and delete during review (#66). This ADR is the core half of the second round (slice 3b-core of the phase 1 brief); the app half follows.

Issue #50 listed three edge cases from the #49 review. They are fixed here, because they are in the same code.

## Decision

### Method

The method of ADR 0025, amended by ADR 0049, unchanged: proptest in the gate, generated from syntax; time bounds on the CPU time of the thread that did the work (`fastest` and `assert_cpu_within`, or `within` with its separate hang limit); bounds about ten times the slowest measured value in a debug test build; scales of 5,000 cards (`storage/tests/perf.rs`). No existing bound was raised. Each oracle test was checked against a broken copy of the code it guards (an unquoted query, a reset picked by the wrong tie-break, a finish restore that prunes): each fails.

## Consequences

- A search reads only the first 1 KiB of its folded words, counted from each word's first letter or digit; spaces and padding do not count. So this is no limit on what may be typed: the app must not cut its search entry at 1,024 bytes (or `MAX_QUERY_BYTES`), which would hide words behind padding again.
- `cargo test -p rappel-core` takes about 5 s longer (54 s against 58 to 61 s, runs side by side on the maintainer's laptop under the same load), mostly building the 5,000-card and 20,000-entry stores; the new properties run 128 cases each.
- A data folder whose clock once ran ahead keeps up to 14 more backups until those dates pass.
- After Finish Restore, every backup stays until the next start.
- New entry points (images, audio, Anki import) add their rows here or in a later round.

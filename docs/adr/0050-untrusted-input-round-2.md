# 50. Untrusted input, round 2

- Status: Accepted
- Date: 2026-10-18
- Amends: ADR 0025 (new entry points, same method), ADR 0026 (rule 4 of backup retention; finishing a restore prunes nothing), ADR 0035 (what a search reads of the query), ADR 0016 (Start Fresh past a waiting copy that cannot be used, row 35), ADR 0039 (how the window state is read, row 33), ADR 0043 (at most 100 tags from the tags field, row 30)
- Closes: #50

## Context

ADR 0025 reviewed every place where content Rappel did not write itself comes in, merged at #47. Since then the core gained new ways in: backup retention and restore loose ends (#49), settings (#51), undo, reset, tags and export format 2 (#52), statistics and card information (#59), the search index, suspension and bulk writes (#63), and suspend and delete during review (#66). The core half of the second round (slice 3b-core of the phase 1 brief) is rows 15 to 29. The app half (slice 3b-app) reviews what the app gained since #47 (`git log 7c4d92a..phase-1 -- crates/app`): tags in the editor, the deck page and All Cards, search and type-to-search, bulk actions, suspend and delete during review, the statistics page, the Card Information dialog, the preferences, the window-state file, the startup pages and the UI overhaul (#72 to #80); it is rows 30 to 38.

Issue #50 listed three edge cases from the #49 review. They are fixed here, because they are in the same code.

## Decision

### Method

The method of ADR 0025, amended by ADR 0049, unchanged: proptest in the gate, generated from syntax; time bounds on the CPU time of the thread that did the work (`fastest` and `assert_cpu_within`, or `within` with its separate hang limit); bounds about ten times the slowest measured value in a debug test build; scales of 5,000 cards (`storage/tests/perf.rs`). No existing bound was raised. Each oracle test was checked against a broken copy of the code it guards (an unquoted query, a reset picked by the wrong tie-break, a finish restore that prunes): each fails.

### Entry points: the app

The same method, with the app's copies of the helpers (`testing::cpu_within`, `within`, ADR 0049). The app's GTK tests time the work on the GTK thread, in CPU time. Two limits of GTK itself matter below: a `GtkText` (the search field, the tags field) keeps at most 65,535 bytes of what is pasted (`GTK_ENTRY_BUFFER_MAX_SIZE`), and nothing the app shows parses markup unless it was escaped first (ADR 0025, rows 2 and 4).

## Consequences

- A search reads only the first 1 KiB of its folded words, counted from each word's first letter or digit; spaces and padding do not count. So this is no limit on what may be typed: the app must not cut its search entry at 1,024 bytes (or `MAX_QUERY_BYTES`), which would hide words behind padding again.
- `cargo test -p rappel-core` takes about 5 s longer (54 s against 58 to 61 s, runs side by side on the maintainer's laptop under the same load), mostly building the 5,000-card and 20,000-entry stores; the new properties run 128 cases each.
- A data folder whose clock once ran ahead keeps up to 14 more backups until those dates pass.
- After Finish Restore, every backup stays until the next start.
- The tags field adds at most 100 tags to a card; an import has no limit, and a card with more keeps them.
- A waiting restore copy that cannot be used is renamed to `rappel.sqlite3.restore.refused-…` by Start Fresh when there is no backup, and kept.
- A `window-state.ini` larger than 4 KiB, or one that is not a regular file, is ignored: the window opens at its default size.
- The filter drop-downs now ellipsize as ADR 0044 meant, and their popups wrap long names.
- `cargo test -p rappel` takes about 2.6 s longer (8.9 s against 11.5 s, run one after the other on the maintainer's laptop), mostly the 5,000-pill layout, the 20,000-name paste and the search delay.
- New entry points (images, audio, Anki import) add their rows here or in a later round.

# 48. Shared UI helpers after the overhaul

- Status: Accepted
- Date: 2026-10-17
- Amends: ADR 0039 (how the window state file is written), ADR 0044 (the accessible names of the selection buttons)
- Refers to: SPEC §4.10, #20, `docs/briefs/phase-1-finish.md` (slice 2)

## Context

The seven UI slices (#72–#78) each solved the same small problems on their own screen. Four places checked "is a page of this type already on top?" before a push (key repeat, #20), and `win.search` relied on its own check. Four places connected a breakpoint's `apply` and `unapply` to the same setter. The deck page and All Cards had the same 40-line row factory. Two text modules collapsed whitespace the same way, and minutes, hours and days were defined three times. Reviews of the slices also left a few open points: the window state was written and then narrowed to 0600, the focus of a deck page reopened at startup was never set on purpose, and the action buttons of All Cards had accessible names that did not match.

## Decision

**One way to push a page.** `ui::nav::push_unless_on_top(view, build)` builds and pushes a page unless the visible page is already of that type (or a subclass); `build` does not run then, so a repeated key reads nothing. Every page push goes through it: the deck list (deck page, Statistics), the deck page (review, Statistics) and `win.search` (All Cards). The check holds at once, because `push` appends to the navigation stack and `visible_page` is its last item, both synchronous in `adw-navigation-view.c` (source read for libadwaita 1.8 and 1.9; built and tested against 1.10.0 and GTK 4.24.1).

**Focus when a deck page is shown.** `shown` is where a pushed page sets its focus (CLAUDE.md). On a push from the deck list, `AdwNavigationView` already moves the focus into the new page (`switch_page`: `gtk_widget_child_focus` on the page when the focus was in the page below), and on a pop it gives back the widget that had it. At startup there is no focus yet: the window is not shown when `restore_state` pushes the deck page without animation. That push still emits `shown`, synchronously: with animations off `switch_page` skips the transition, and the skip runs `transition_done_cb`, which emits it. So the deck page's `shown` handler keeps a focus that is already inside the page and otherwise focuses the first card, or Add Card when the deck is empty (the pure `ui::focus::when_shown`). `GtkWindow` then keeps that focus widget when it is shown (`gtk_window_show` moves the focus only when there is none). Before, the focus landed on the first card only because `AdwToolbarView` puts its content before the top bar in the focus chain; now it is meant, and a test checks it on a window that is not shown. (Source read: `adw-navigation-view.c` and `adw-animation.c` for libadwaita 1.8 and 1.9, `adw-toolbar-view.c` for 1.9, `gtkwindow.c` for GTK 4.22; the test runs against 1.10.0 and 4.24.1.)

**Buttons with an `AdwButtonContent` child.** The content makes its label the button's mnemonic label when it is rooted (`adw_button_content_root`), which sets the button's labelled-by relation (`gtk_widget_add_mnemonic_label`), and GTK's name computation takes a labelled-by relation before the label property (`gtk_at_context_get_text_accumulate`, steps 2B and 2C). So All Cards' Move button was read as "Move…" while the Tags menu button was "Tags of selected cards", and on a phone, where the breakpoint empties the words, the buttons had no name at all. (Source read: `adw-button-content.c` for libadwaita 1.9 and main, `gtkwidget.c` and `gtkatcontext.c` for GTK 4.24; observed over AT-SPI with 1.10.0 and 4.24.1.) All Cards now resets that relation once its children are rooted (in its `root` vfunc), so each button is named by its own accessible label, at every width. Only the relation is reset: the mnemonic label stays, so Select All's "_All" still works. A GTK test checks, with `gtk_test_accessible_has_relation` and `gtk_test_accessible_has_property`, that none of the five buttons has a labelled-by relation and each has a label, once rooted and again at 360 px with the breakpoint applied, and that an ordinary button with an `AdwButtonContent` does have the relation. The Suspend button's tooltip is its word ("Suspend", "Unsuspend"), as the other buttons' are; its accessible label stays "Suspend selected cards". A button with an `AdwButtonContent` and a label of its own needs the same treatment.

**Small shared pieces.** `ui::breakpoint::follow` calls a closure with `true` or `false` on `apply` and `unapply`. `card_row::factory` is the row factory of both card lists. `ui::text::one_line` and `unit_count` and `ui::time::{MINUTE_MS, HOUR_MS, DAY_MS}` replace the local copies; `testing::temporary_state` is the tests' one temporary database. A helper was added only where it makes every caller shorter: the pages' one-line `error_toast` wrappers and the two `position` scans over different item types stay as they are.

**The window state file.** `save` writes it with `g_file_set_contents_full` (`G_FILE_SET_CONTENTS_CONSISTENT`, mode 0600): a temporary file created with that mode is renamed over the old one, so a new file is never readable by others, not even between the write and a `chmod`. GLib keeps the mode of a file that already exists (its docs, and `fchmod` from the old file's mode in `gfileutils.c`), so a file with a wider mode is then narrowed to 0600, as core's `prepare_private_file` does for the database's files.

## Consequences

- A new page is pushed with `push_unless_on_top`; a page whose `shown` sets the focus should keep a focus already inside it, as the deck page does.
- `restore_state`'s focus depends on libadwaita emitting `shown` during an unanimated push. If a later libadwaita defers it, the startup focus falls back to `GtkWindow`'s first focusable widget (still the first card, through `AdwToolbarView`'s order), and the window test fails, so the change is noticed.
- Resetting a relation that `AdwButtonContent` set is a workaround; if libadwaita stops setting it, the reset does nothing.
- The test checks the inputs of the name (no labelled-by relation, a label property); the name a screen reader finally hears is checked by hand (the PR checklist), since GTK has no public call that returns a computed accessible name.

# Changelog

All notable changes to this project are documented here.
The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and the project aims to follow [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Fixed
- **Playing an MP3 with tags no longer closes Rappel** (ADR 0062). GStreamer stopped the whole app on the ID3 tag most MP3 files start with; Rappel now plays an MP3's audio without its tags (it shows no tags anyway).
- **Importing a file with many pictures and sounds is many times faster** (ADR 0063): the files are written to disk together instead of one after another, as safely as before (10,000 small files: 3 s instead of 68 s).
- **The first audio played after installing or updating starts in a fraction of a second** instead of holding the window for one to two seconds (ADR 0062): GStreamer now looks only at the plugins Rappel lets it use.
- **On a phone, the on-screen keyboard no longer hides the field you type in** (ADR 0058): when the window gets shorter, the focused field (the card editor's sides and tags, Add Tags, a deck's name, Preferences) is scrolled back into view, and a text field keeps its cursor in view.
- **The card editor's tags are easy to tap and never cut** (ADR 0058): each tag is a pill with libadwaita's full-size remove button, and shows its whole name, wrapping when it is wider than the field.
- **On a narrow window, the editor's preview scrolls with the keyboard** (ADR 0058): switching to Preview puts the focus on it, and Up, Down, Page Up, Page Down, Space, Home and End scroll it.
- **Toasts are no longer cut with "…" on a phone** (ADR 0058): a long message shows a short title with a **Details** button that opens the whole text (errors, the export and import messages, the recovery messages with their file names, the start-up warnings). Undo toasts are short: the clean-up says "12 files trashed", and All Cards and the deck list say "3 cards moved", "3 cards tagged", "3 cards untagged", "1,000 cards reset" or "Deck deleted"; cards Add Tags left out are said in a second toast.
- **Held sideways, the review page shows the answer** (ADR 0058): after Show Answer, the card scrolls to the answer if it starts below the view, and images are sized to the card's own space between the header and the buttons.
- **Held sideways, the start-up pages and the empty states fit** (ADR 0058): "Database Is Damaged", "Update Rappel to Continue", "Rappel Could Not Start", "No Decks Yet", "No Cards Yet", "No Statistics Yet" and All Cards' empty states drop their large icon or shrink it, so their text and buttons are on screen.
- After **Clean Up…** in Preferences, the focus stays on the Clean Up Media row instead of jumping to the top.
- **On a small window, a question that deletes or moves something no longer has its destructive answer focused** (ADR 0057): Delete Card?, Start With an Empty Database?, Restore This Backup? and Clean Up Media? now always open with Cancel (or Keep Editing) focused, so Enter or Space never answers the destructive way. libadwaita focused the last answer at phone sizes.
- **Importing a large file no longer needs memory in proportion to it** (ADR 0053). Import reads the file from disk as it goes and keeps only small notes of what it has read: measured at most about 150 MB at the largest file an import takes, where it used to take up to about 950 MB, and files crafted to make a zip reader hold memory or work for long are refused at once. It still checks the whole file before anything is imported, and still imports nothing if anything is wrong.
- **A file that changes after it was checked is not imported** (ADR 0053): the import reads the file again, and if it is no longer the file you confirmed, it says "The file changed since it was checked" and imports nothing.
- **A damaged setting no longer stops Rappel with no way on** (ADR 0052). If a value in the database's settings cannot be read (a hand edit, a damaged file), Rappel shows **A Setting Is Damaged**, names the setting as Preferences does and says what its default is. **Reset This Setting** makes a backup first, then puts that one setting back to its default and opens your decks; nothing else is changed. If another setting is damaged too, the page then shows that one.
- **Restoring a backup keeps the copy an interrupted restore left waiting** (ADR 0052): it is kept as `rappel.sqlite3.restore.set-aside-` and the date and time in the data folder, never replaced, and the notice after the restore says where.
- **Tag suggestions only offer tags a card has** (ADR 0052): a typo tag that was taken off again is no longer suggested in the card editor or in Add Tags, and no longer listed in the All Cards tag filter (unless it is the one chosen there). No tag is deleted.
- **Reset Progress is greyed out for a card that is already new** (no review since it was created or last reset, or only reviews that were undone), in the card menu of the deck page and of All Cards. A reset of such a card used to add a log entry that changed nothing. In selection mode, **Reset Progress** is offered while at least one chosen card has progress, and leaves the new ones alone. If a menu is stale and the core refuses, the page says "This card has no progress to reset" and updates the row.

### Changed
- **Audio is decoded only by plugins Rappel allows** (ADR 0062): GStreamer may load just the 21 plugins that playing Ogg, MP3, M4A and WAV needs, in a plugin registry of Rappel's own. FFmpeg's plugin is not among them, so an M4A file in Apple Lossless, or one in AAC on a system whose only AAC decoder is FFmpeg's, says "Could not be played". Install GStreamer's `faad` (`gstreamer1.0-plugins-bad`) or `fdkaac` for M4A files.
- `rappel-core`: new `Store::plan_anki_import` and `Store::apply_anki_import` (both take a cancel flag), `interchange::file_kind`, `Error::AnkiRefused` and `Error::ImportCancelled`. New dependency `ruzstd` (MIT) for zstd; `rappel-core` also uses `ratex-parser`.
- Numbers are grouped everywhere ("1,000 years", "in 1,000 years"); a few places printed them without a separator.
- Development: `scripts/screenshot.py` has `--decoration-layout` (e.g. `:close`, as GNOME and phones show window buttons).
- **Card Information lists the card's tags** in full (ADR 0058), so the names a row shortens or counts in "+N" can be read on a touch screen.
- **Statistics' empty state** offers Back to Decks / Back to Deck as a plain button: going back is not the page's suggested action.
- Development: `scripts/screenshot.py` has a `resize:W,H` step, to see a screen with a phone's on-screen keyboard up.
- `rappel-core`: `plan_import` and `apply_import` stream the archive (ADR 0053). The file may be up to 2 GiB with up to 100,000 entries (a zip64 end record is read); `cards.json` stays at 256 MiB. A string longer than any field can be (6 MiB), or nesting deeper than 1,024 levels, refuses the file as JSON. The archive is read by Rappel's own code (only the declared central directory, record by record), not by the `zip` crate's reader; Deflate through `flate2`, CRCs through `crc32fast`. `ImportPlan` holds a fingerprint of the file instead of its content; `apply_import` reads the file again and refuses a changed one with `Error::ImportFileChanged`. New: `ImportProblem::TooManyEntries`.
- `rappel-core`: a stored setting that is not valid is `Error::DamagedSetting { key, .. }` (was `Error::InvalidColumn`), and `Store::open` refuses it after migrating, naming its key (`domain::SettingKey`). `restore_backup` sets a waiting restore copy aside (`Restored::set_aside`) and refuses, changing nothing, when something other than a regular file has its name.
- `rappel-core`: `Store::reset_card` refuses a new card with `Error::CardAlreadyNew`, and nothing is written; `Store::reset_cards` skips new cards and returns only the entries it wrote.

### Added
- **Import from Anki** (ADR 0061). **Import…** now also takes Anki packages (`.apkg`, and `.colpkg`, the whole collection), from Anki 2.0, 2.1 and the current versions. Each Anki card becomes a plain Markdown card, in a deck of the same name ("A::B" becomes "A › B"); reversed notes give a card per direction, and a cloze card hides its cloze on the front and shows it in bold on the back. Tags, images and sounds, suspended cards and the review history come along (Again is Fail, the other buttons Pass), and the schedule is worked out from that history. Before importing, Rappel lists what it leaves out or changes, with examples; nothing is ever fetched from the web, and SVG images are never shown. Importing the same package twice adds nothing. Reading and importing can be cancelled.
- `fill_scratch_db --anki PACKAGE` imports an Anki package into scratch data.
- **Desktop integration drafts** (ADR 0060): a desktop entry and AppStream metainfo for software stores (summary, description, releases, content rating, five screenshots of the app) in `data/`, with **placeholder** icons, all translated into French. Nothing installs them yet; packaging comes later. The tests validate them with `desktop-file-validate` and `appstreamcli` and keep them in step with the code and this changelog; running the tests now needs the `appstream` and `desktop-file-utils` packages.
- `fill_scratch_db --demo`: six decks that look like a real collection (capitals, French words, chemical elements, art history, calculus with formulas, flags as pictures) with a month of review history, for screenshots.
- **Rappel speaks French** (ADR 0059). With a French system language, every text of Rappel is in French, with French plurals, numbers ("5 210", "91 %") and dates. The translation still has to be proofread. Rappel's own error details (the part after "Details") stay in English, and GTK's and libadwaita's own texts need the system's French language pack.
- Translators: Rappel uses gettext (`po/`); see README.md for how to add a language or update one.
- **Clean Up Media in Preferences** (ADR 0057). The new **Storage** group says how many media files no card uses and how much space they take ("12 unused files, 4.3 MB"); **Clean Up…** asks first, then moves them to a trash folder in Rappel's data folder (`media-trash`), with Undo in the notice. A file counts as used while any card names it, including deleted cards (so Undo of a deletion always has its images). Files stay in the trash for at least 30 days and are then deleted when Rappel starts, except those a backup still uses; restoring a backup, importing a file, or saving a card that names a trashed file brings it back. This is the only time Rappel deletes one of your files.
- `rappel-core`: `Store::unused_media`, `Store::clean_up_media` / `undo_clean_up` (`CleanedUp`), `Store::tidy_media_trash` (`TrashTidied`), `media::PURGE_AFTER_DAYS`, `Error::ClockWrong`. `Store::open`, `restore_backup`, `finish_restore`, `apply_import` and every card write bring back the trashed media files they use; `add_media` names its file and records it under the database's write lock.
- Development: `fill_scratch_db --unused-media` adds three media files no card names.
- **Audio on cards** (ADR 0056). A link to an Ogg, MP3, M4A or WAV file of the card (`[words](media:…)`) is a play button with its words; the time played shows beside it. Nothing ever plays by itself: press the button (or Tab to it and press Space or Enter), or press **R** on the review page to play the card's audio from the start (the answer's once it is shown, else the question's). One sound plays at a time, and it stops on the next card, when you edit or leave. A sound whose file is missing says "Audio not available"; one that cannot be played says so and can be tried again. Screen readers hear "Play audio:" and the link's words. Playing needs GStreamer's usual plugins, which GNOME systems have (an AAC decoder for M4A files). Only plain audio is played or kept: an audio file must be well-formed MP3, Ogg Opus or Vorbis, PCM or float WAV, or M4A sound over its whole length, so a playlist or stream description dressed up as audio (which GStreamer would follow to other files or the network) is refused when added, imported or played, and GStreamer's streaming and network elements are switched off inside Rappel. Which GStreamer decoder plays a file is still GStreamer's choice. Without GStreamer's base plugins, audio buttons say "Audio playback is not available on this system" instead of playing.
- **Adding audio in the card editor**: the **Insert Audio…** button beside Insert Image… on Front and Back, or paste or drop audio files on a side (dropped or pasted files go in as images or audio by what they are, whatever their names say). The link goes in with the cursor ready for its words. A file that is not an Ogg, MP3, M4A or WAV audio file, or is larger than 20 MB, is refused with a notice saying why. No recording.
- **Images on cards** (ADR 0055). PNG, JPEG, WebP and GIF images (a GIF shows its first frame; SVG is never shown) appear in the card on the review page and in the editor's preview, scaled down to the card's width and to part of the window's height, never enlarged. Click an image, or Tab to it and press Enter or Space, to see it at full size; Escape closes it. Its alt text (`![alt text](…)`) is what screen readers say. An image whose file is missing or cannot be shown is a dimmed line saying so, with its alt text. Images are decoded in a separate process, sandboxed by bubblewrap where the system allows it (most desktops; in a Flatpak, the Flatpak sandbox), so a damaged or hostile file does not run inside Rappel; where no sandbox can be made (some containers), the decoder still runs as a separate process but without the sandbox, and Rappel logs a warning. This needs the `glycin-loaders` and `bubblewrap` packages, which most GNOME systems have.
- **Adding images in the card editor**: the **Insert Image…** button beside Front and Back, pasting an image or image files with Ctrl+V, or dropping image files or an image on a side. Only files on this computer are added; a web address is never downloaded ("Only files on this computer can be added"), when a browser offers both an image's address and the image, the image itself is taken, and a copied link still pastes as text. The image goes where the cursor (or the drop) was, with the cursor ready for its alt text; one Ctrl+Z takes it out again. A file that is not a PNG, JPEG, WebP or GIF image, or is larger than 10 MB, is refused with a notice saying why. An image added to a card you then do not save stays in Rappel's media folder until unused media can be cleaned up.
- `rappel-core`: `Store::add_audio` (only audio; an image is refused as `MediaProblem::NotAudio` before anything is written) and `media::check_structure`: an audio file is accepted by `add_media`, the import and the export only if all of it is plain audio of its kind, else `MediaProblem::Malformed` (damaged) or `MediaProblem::NotPlainAudio` (holds more than plain audio); an import refuses it as not of its type, an export leaves it out as damaged.
- `rappel-core`: `Store::add_image` (only images; an audio file is refused as `MediaProblem::NotImage` before anything is written) and `Store::media_folder`.
- Building: the image decoder glycin needs the development files of Little CMS 2, libseccomp and fontconfig (README).
- **Media files in the export** (ADR 0054). A Rappel export now carries the images and audio files of your cards, each stored as it is under `media/` in the file, and an import puts the new ones into Rappel's media folder (only after checking every one of them: a file whose media are not what they claim is refused and nothing is imported). If a media file is missing or damaged when you export, the rest is exported and a notice says how many files could not go in. An export with media cannot be imported by 0.2.0.
- `rappel-core`: the media store (ADR 0054): `Store::add_media` / `add_media_bytes` (a file kept as `<data dir>/media/<sha256>.<ext>`, its type read from its first bytes: PNG, JPEG, WebP, GIF, Ogg, MP3, M4A, WAV; up to 10 MB per image and 20 MB per audio file; SVG and anything else refused), `Store::media_path`, `media::MediaRef` and `MediaKind`; `content::media_refs`, `ImageTarget::Media(MediaRef)` and `Inline::Audio` for a link to an audio file. Migration 0011 adds the `media` table (a backup is made first). `ImportSummary::media`, `ImportReport::media`, `ExportSummary::{media, missing_media}`, `Conflict::MediaDiffers`, new `FieldProblem`s for media records, `Error::{MediaRefused, MediaRead, NoMediaDir}`; `ImportProblem::UnsupportedMedia` is gone.
- Development: `fill_scratch_db --media` adds a "Media" deck with generated images, a WAV tone (on a back and on a front), a missing image and a missing sound, and a remote image.
- Development: `scripts/screenshot.py`, the batch-mode screenshot harness (a private Xvfb display, input only through XTest).
- `rappel-core`: `storage::reset_setting(data_dir, key)` (a backup, then the one damaged row removed and, for the retention, the schedule rebuilt, in one transaction; returns `SettingReset`), `Error::InstalledWithDamagedSetting` (a restored backup with a damaged setting: where the old files went) and `Store::used_tags` (the tags at least one live card has).
- `rappel-core`: `Error::CardAlreadyNew`; `Store::new_card_ids(deck)` lists a deck's new cards in one query; `BrowseRow::is_new` says whether a card is new, also when it is suspended.

## [0.2.0-beta.1] — 2026-10-18

### Added
- **Add Tags in All Cards uses the card editor's tag field** (#65, ADR 0051). The selection mode's **Add Tags…** suggests the tags you already have as you type, with the same keys (Down / Up, Tab, Enter, Escape), so bulk tagging no longer makes typo tags. Several tags can be added at once, as pills, and one Undo takes them all back. A card that would end up with more than 100 tags is left out, as in the editor, and the toast says how many were.
- `rappel-core`: `Store::add_tags_to_cards` (several tags on many cards in one write, with a limit per card, `TagsAdded`) and `Store::release_tags`, its Undo. They replace `add_tag_to_cards` and `release_tag_from_cards`, which are removed.
- **Keyboard Shortcuts** (#53, ADR 0039): **Ctrl+?** or **Keyboard Shortcuts** in the main menu lists every shortcut, grouped by screen (general, studying, card editor, All Cards, statistics charts). Menu items that have a key show it, e.g. **Suspend Card S** in the review page's Card Menu.
- **About Rappel** in the main menu: version, licence (GPL-3.0-or-later), the repository and issue tracker, the libraries Rappel is built with, and the copyright and licence (SIL OFL-1.1) of the KaTeX fonts.
- **Rappel remembers its window**: the size, whether it was maximised, and the deck whose page was open when it closed, which opens again at the next start (a review is not resumed; a deck deleted since is skipped). Kept in `window-state.ini` in the data folder, not in backups or exports.
- **Suspend and Delete during a session** (SPEC §4.5, ADR 0037). The ⋮ menu of the review page has **Suspend Card** and **Delete Card…**, also on the keys **S** and **Delete**. The card leaves the session at once (it is not counted as answered) and the next card appears; a notice offers **Undo**, which puts the card back to be studied next. Holding **S** does not suspend a run of cards: a card must have been on screen for a moment first. Delete asks first, with Cancel as the default, and keeps the card's history. A card suspended meanwhile, from another window say, is skipped, and Ctrl+Z on an answer to a card suspended since still takes the answer back without showing that card.
- `rappel-core`: `Session::put_back`, the inverse of `skip`; `Session::undo_last` no longer queues a card twice.
- **All Cards** (SPEC §4.6, ADR 0036). A search button in the deck list's header and **Ctrl+F** open a page with every card. Type to search what you read (case and accents ignored, each word matched as a prefix), narrow by deck, tag and state (new, learning, due, suspended), and open a card's editor or Card Information from its ⋮ menu. **Select** (or **Ctrl+A**, or a long press on a touch screen) chooses several cards: move them to a deck, add or take off a tag, suspend or unsuspend, reset progress, or delete, each with an Undo toast that says how many cards it could restore if some changed meanwhile. Wide windows show the back and the tags of each card; at 360 px the rows and the buttons are compact. Ctrl+F on a deck page opens the page filtered to that deck. Keyboard: **Down** from the search field to the list, **Enter** opens a card, **Space** chooses it in selection mode, **Escape** leaves selection mode, then clears the search. With 5,000 cards the page opens in about 50 ms and a search takes about 20 ms (debug build).
- **Suspend** in each card's ⋮ menu on the deck page (with an Undo toast); suspended cards leave study and show "Suspended".
- `rappel-core`: the search index, suspension and bulk writes for the coming All Cards page (SPEC §4.6, ADR 0035; no screen yet). Search is full text over what you read, not the Markdown: `**bold**` is found by "bold", the address behind a link is not found; case and accents are ignored ("economie" finds "Économie") and each word matches as a prefix. `Store::browse` filters by text, deck, tag and state (new, learning, due, suspended); at 5,000 cards it takes under 30 ms and at 20,000 under 50 ms in a debug build. A card can be suspended: it leaves study, the deck counts and the statistics' forecast and retention, and keeps its content, tags and history. `set_suspended`, `move_cards`, `add_tag_to_cards`, `remove_tag_from_cards`, `reset_cards`, `delete_cards` change many cards in one all-or-nothing write and say exactly what changed, so each can be undone (`unmove_cards`, `undo_entries`, `undelete_cards`, …). Migrations 0009 (the flag) and 0010 (the index, filled for your existing cards; a backup is made first).
- **Export format 2 has `suspended`** on each card (always written; a file without it reads as not suspended, so older files still import). An import never changes whether an existing card is suspended. An export made after this change cannot be imported by 0.2.0-alpha.3 (it names a field that build does not know).
- `fill_scratch_db --suspended N`: suspends the last N scratch cards.
- **Statistics** (SPEC §4.7, ADR 0033). **Statistics** in the main menu shows all decks; the ⋮ menu of a deck page shows that deck. Three headline numbers (expected retention, pass rate and time studied over the last 30 days) sit above three charts: reviews per day (passes solid, fails hatched, so they differ without colour), time studied per day, and the cards due over the next 14 days. A chart can be focused: **Left**, **Right**, **Home** and **End** (or a click or tap) pick a day and say its values. Each chart also has a summary for screen readers ("Last 30 days: 412 reviews, 380 passed, busiest day 14 October with 38."). Colours follow the theme and accent colour. With nothing studied yet, the page says so.
- **Card Information** (#39): the ⋮ menu of each card on the deck page, and a ⋮ menu in the review header or the **I** key. It shows when the card was created and edited, its reviews, pass rate and lapses, stability, difficulty, recall now, next due, and its history, newest first, with each reset as a row of its own. Opening it during a session changes nothing.
- `rappel-core`: statistics and card information (SPEC §4.7, #39, ADR 0032; no screen yet). `Store::stats(scope, now, past, ahead)` gives, for all decks or one: reviews, passes and time studied per day over the last 30 days, the pass rate, the due forecast for the next 14 days with the overdue count, and the expected retention today (mean FSRS retrievability). `Store::card_info(card, now)` gives a card's dates, reviews, lapses, pass rate, stability, difficulty, retrievability, next due and history (reviews with grade and interval, resets as markers). Undone reviews and deleted cards or decks never count; a reset restarts a card's memory (retention, forecast, reps) but leaves the past days' reviews, time and pass rate as they were. Days are cut at the day start hour the app passes in, daylight saving included. At 5,000 cards and 100,000 reviews the statistics take about 0.3 s in a debug build.
- **Tags in the card editor** (SPEC §4.4, ADR 0031). A **Tags** field under Back takes names separated by commas. While you type a name, the tags that exist are suggested in a list under the field, ignoring case and accents ("eco" finds "Économie"): **Tab** takes the highlighted suggestion, or the first, **Down** / **Up** highlight one (nothing is highlighted to start), **Enter** takes a highlighted one and otherwise keeps what you typed, and **Escape** closes the list. The card and its tags are saved together, with **Ctrl+Enter** or **Ctrl+Shift+Enter**; the latter keeps the tags for the next card, which suits adding a batch. An empty name ("a,,b") or one over 256 bytes shows an error under the field and disables saving. Taking a tag off a card only unlinks it; the tag itself stays (ADR 0029).
- **Tags on the deck page**: each card row shows its tags, dimmed, after the front, cut off with an ellipsis when they do not fit; screen readers read them after the front.
- `rappel-core`: `Store::add_card_with_tags`, `edit_card_with_tags` (one write for the card and its tags; a change to the tags alone leaves `updated_at` alone), `list_tagged_cards` (cards with their tags in two queries), and `domain::{parse_tag_field, search_key, TaggedCard}`.
- `fill_scratch_db --tags`: tags on the scratch cards (accents, case variants, a long list, none).

### Fixed
- **Screen readers on the review page** (#48, ADR 0051): the card itself now has a name. The card area's text and the "only its start is shown" note were set for screen readers but never reached them (a plain box has no accessible name in GTK); now the focused card reads its front, and its back once shown, each with the note when it is cut, and the note is no longer exposed a second time on its own. Labels with long unbroken runs (a hash, a long URL) are named without the invisible break characters added for layout.
- **Hardening, round 2** (ADR 0050): the attack tests of ADR 0025 now cover everything the core gained since: searches, tags, settings, the log's undos and resets, statistics, and backup retention and restore. What they found is fixed:
  - **The deck list and deck page stay fast with a long history.** A card reviewed thousands of times (from an import, or years of study) made the daily counts slow down with the square of its reviews: 7 s for one card of 8,000 reviews in a debug build. It now takes 17 ms.
  - **Searching for something pasted no longer freezes.** The same word typed thousands of times, or one long word of hyphenated pieces, took up to 10 s on 5,000 cards. Repeated words (and words that start another word of the search) are now looked up once, which finds the same cards, and only the first 1 KiB of a search (about 150 words) is read.
  - **A card with thousands of tags saves quickly.** Setting 5,000 tags took 0.6 s and grew faster than the count; it now grows in step with it.
  - A damaged settings value is quoted only in part in its error message.
- **Hardening, round 2, the app** (ADR 0050, rows 30 to 38):
  - **Pasting a long list into the tags field no longer freezes the editor.** 20,000 names took over a second and made a pill for each. The field now adds at most **100 tags** to a card and says "A card can have at most 100 tags" under it; the names past that stay in the field, so nothing is lost. A card imported with more tags keeps them.
  - **A card with thousands of tags no longer slows its row.** The "+N" pill's tooltip and what a screen reader hears name the first 20 tags and say how many more there are.
  - **The filter drop-downs of All Cards** end a long choice in "…" as they were meant to, and their lists wrap long deck and tag names instead of growing wider than the window.
  - A tag name with a line break shows on one line in the suggestions too, and a name written right to left no longer reorders the text after it in a row's caption or tooltip.
  - **Rappel no longer hangs at start** if its `window-state.ini` is replaced by a pipe; a file that is not a small regular file is ignored, and a saved size larger than the screen is cut to it.
  - Statistics and Card Information no longer overflow on huge counts or far-off dates, and show "—" instead of "NaN%".
  - **No dead end after an interrupted restore with a damaged copy.** If Finish Restore finds the waiting copy unusable and there is no backup, the page now says so and offers **Start Fresh**, which renames the copy to `rappel.sqlite3.restore.refused-…` and keeps it. The error toast no longer hides the one that says what was done.
- **Restore edge cases** (#50): with a stray `-wal` file next to a restore that did not finish, the start page now offers **Finish Restore** instead of saying the database is missing. Finishing a restore no longer deletes any old backup, so the one it came from stays. And backups made while the computer's clock ran ahead are kept like others (the newest of each day, for up to 14 such days) instead of all but one being deleted once the clock is put right.
- `rappel-core`: `MAX_QUERY_BYTES`, how much of a search query is read.
- `rappel-core`: `Restored::set_aside`, where `start_fresh` moved a waiting restore copy that could not be used.
- `rappel-core`: `storage::is_unusable_copy`, whether a failed check of a restore copy refused its content (only then does Start Fresh set the copy aside), and `Error::WalModeCopy`, the refusal of a copy in WAL mode (was an IO error).

### Changed
- Internal: the tests' time bounds hold on a busy machine (#67, ADR 0049). They measure the CPU time of the thread that did the work instead of the wall clock, and when a time is over its bound they compare it with a reference workload run at once on the same thread, so a machine slowed by load is measured at its own speed. A hang is caught by a separate, generous wall-clock timeout. The bounds themselves are unchanged and still fail the regressions they are there for. With three busy loops per CPU, `cargo test` used to fail 7 to 11 tests per run; it now passes.
- Internal clean-up (SPEC §4.10): every page is pushed through one helper that never stacks a second page of the same kind (#20), the deck page and All Cards make their rows with one factory, breakpoints are followed through one helper, and shared texts, time constants and test helpers replace local copies. - ADR 0002: GTK/libadwaita minimum versions and the Blueprint build pipeline.
- CI: GitHub Actions workflow running `scripts/check.sh` on pull requests and pushes to `main` in an Ubuntu 26.04 container, with cargo caching (ADR 0003).
- Data directory: `CARDS_DATA_DIR`, else `$XDG_DATA_HOME` (default `~/.local/share`) + `cards` (release) or `cards-dev` (debug). Created with mode `0700`. Debug builds refuse the release directory. Path logged at startup; a toast appears if it cannot be created (ADR 0004).
- Dependencies: `thiserror` (core error type, as SPEC requires), `tempfile` (dev-only, for filesystem tests).
- Storage (ADR 0005):
  - `Store::open` with WAL, foreign keys, `synchronous=FULL` and an integrity check that refuses to open a damaged database.
  - A numbered migration framework that runs each migration in its own transaction. Old migrations are hash-pinned by a test.
  - Migration 0001: `decks`, `cards`, append-only `review_events` (enforced by triggers), and the `card_schedule` cache. Ids are UUIDv7 TEXT; timestamps are UTC ms.
  - Online-API backups before migrations and once per UTC day, keeping 14. The backup just made is never pruned. A failed daily backup or prune only logs a warning; a failed pre-migration backup stops the migration.
  - Damaged, too-new and non-Cards database files are refused before anything is written to them.
  - Files are created with mode `0600`, directories with `0700`.
- Dependencies: `rusqlite` with bundled SQLite (storage), `tracing` in `cards-core` (logging migrations and backups).
- Scheduling (ADR 0006):
  - `Scheduler::schedule` (one review) and `Scheduler::rebuild_state` (replay a card's review log) using FSRS-6 with default parameters and desired retention 0.90 (0.80–0.97 accepted). Fail = Again, Pass = Good.
  - New and failed cards get one 10-minute step. A Pass from the step gives an FSRS day interval.
  - Elapsed days are whole 24-hour periods since the last review, rounded. No time zone is involved.
  - Deterministic interval fuzz (Anki's ranges), seeded from card id and review count, so rebuilds are reproducible.
  - `schedule` refuses a review dated before the card's last review, so the log replays in the order it was recorded. Recording code must store `max(now, last_review_at)`.
  - Domain types `Grade`, `ReviewEvent`, `Phase`, `CardState`.
  - Migration 0002: `card_schedule` recreated with a `phase` column and rebuilt from `review_events` in the same transaction. `Store::review_events`, `Store::card_state`, `Store::rebuild_schedule_cache`.
- Dependencies: `fsrs` (the reference FSRS implementation, as SPEC requires), `proptest` (dev-only, property tests for replay).
- Backup restore in `cards-core` (ADR 0007), no UI yet:
  - `list_backups`: the backups, newest first, with time and size.
  - `restore_backup`: validates the backup (integrity, version, exact schema: object names and their columns) before changing anything. An older backup (e.g. schema v1) is migrated on that scratch copy first, so a failed migration refuses the restore with nothing changed. Moves the current database with its `-wal`/`-shm`/`-journal` aside to `cards.sqlite3.replaced-<timestamp>` instead of deleting it. Installs the backup atomically and opens it. Works when the current database is damaged.
  - `Store::open` refuses to start an empty database when the database file is missing but its `-wal`/`-journal`, or an interrupted restore's copy, is still there.
- README: "Recovering your data".
- Deck, card and review operations in `cards-core` (ADR 0008), no UI yet:
  - `UUIDv7` id generator whose ids strictly increase, within a millisecond, with a clock that goes backwards, and across restarts.
  - Decks: `create_deck`, `rename_deck`, `list_decks` with new / due-now counts, `delete_deck`. Names are trimmed and unique among live decks (`DuplicateDeckName`); a deleted deck's name can be reused.
  - Cards: `add_card`, `edit_card`, `card`, `list_cards`, `delete_card`.
  - Migration 0003: soft delete (`deleted_at` on decks and cards). Deleted items are hidden from every query and keep their review history. Deleting a deck soft-deletes its cards with the same `deleted_at`, so a later undo can restore exactly that batch.
  - `record_review`: the event (dated `max(now, last review)`) and the schedule cache update in one transaction.
  - `due_cards(deck, now)` and `new_cards(deck, limit)`.
  - Property test: after random reviews, clock jumps and restarts, the schedule cache equals a full rebuild from the log.
- Migrations can have a Rust backfill step, run in the migration's transaction (ADR 0010).
- Dependency: `unicode-normalization` in `cards-core` (NFC for deck name keys).
- Dependency: `getrandom` in `cards-core` (random bits for ids; already in the tree through `fsrs`).
- The app opens the database at startup through `AppState` (ADR 0011):
  - The main window shows the empty state "No Decks Yet".
  - A damaged database, a missing database file next to its journal, an interrupted restore, or another application's database shows a recovery page. It lists the backups newest first and restores the chosen one after an `AdwAlertDialog` confirmation, then the app continues.
  - A database from a newer Cards shows a page that explains this and offers no restore.
  - Any other startup failure shows a page with the message, the full error and the data folder.
  - A failed daily backup (or prune) is shown as a toast, not only logged: `Store::open` keeps it as an `OpenWarning` (`Store::take_open_warnings`).
- Deck list on the main page (ADR 0012):
  - Each deck shows its name and new/due counts. With no decks, the empty state has a "New Deck" button.
  - New Deck (header button, empty state, Ctrl+N) and Rename open a dialog. An empty name or a duplicate name (ignoring case and accent composition) disables the button, and a duplicate is explained under the entry.
  - Delete removes the deck at once and offers Undo in a toast.
  - Icon-only buttons have tooltips and accessible labels; the row menu's label names the deck.
- `Store::undelete_deck` in `cards-core`: restores a deleted deck and exactly the cards deleted with it; refuses, changing nothing, if a live deck took its name meanwhile.
- Deck page (ADR 0013):
  - Clicking a deck opens its page, titled with the deck name, with Back, swipe and Alt+← to return. The deck list's counts update on return.
  - The cards are listed by their front on one ellipsised line, in a list view that stays smooth with thousands of cards. With no cards, the empty state has an "Add Card" button.
  - Card editor with plain-text front and back: Ctrl+Enter saves, Ctrl+Shift+Enter saves and starts a new card in the same deck, a blank front disables saving, and closing with unsaved changes asks first.
  - Activating a card edits it; its row menu has Edit and Delete. Delete offers Undo in a toast, which also works after going back to the deck list.
  - Ctrl+N makes a new card on a deck page and a new deck on the deck list.
- `Store::undelete_card` in `cards-core`: restores a deleted card with its history; refuses, changing nothing, while its deck is deleted.
- `cards-core` example `fill_scratch_db`: fills a scratch data directory with 5,000 cards to try the card list.
- Studying (ADR 0014):
  - The deck page has a Study button, disabled when nothing is due and no new card is left for today, and says what there is to study ("3 due · 20 new").
  - The review page shows the front, then the back (Space or Enter), then Fail (1) or Pass (2 or Space). Card text is shown as plain text.
  - Due reviews come first in overdue order, with up to 20 new cards per deck per day spread among them. The study day starts at 4 a.m. local time.
  - Cards in the 10-minute step come back in the same session, and up to 20 minutes early once nothing else is left.
  - Each answer is saved at once, with the time from showing the card to the answer, capped at 60 s.
  - At the end, a summary (cards, pass rate, time) and Back to Deck.
- `cards-core`: `Store::study_input` and the pure `scheduling::session` (queue, interleaving, session, summary).
- `fill_scratch_db --due N`: makes N scratch cards due now, through the real scheduler, to try studying.

### Changed
- `Store::record_review` takes the time of the answer (`now`) from the caller, like the other time-dependent operations.
- Without a usable data folder the app shows an error page instead of starting with a toast.
- Deck names are unique ignoring case and Unicode composition ("Maths" = "maths", composed "É" = "E" + accent); accents still count. Migration 0004 adds and backfills `decks.name_key` (ADR 0010).
- Scheduling: a Pass on a review card is scheduled at least elapsed days + 1 out, before and after fuzz, as in Anki. Migration 0005 rebuilds the schedule cache for the new rule (ADR 0009).
- SPEC §3: ids are TEXT UUIDv7, `cards.seq` is the FTS5 rowid, and card deletion will be a soft delete.
- `Error::CreateDataDir` renamed to `Error::CreateDir` (also used for the backups directory).
- `Error::Random` holds a boxed error instead of `getrandom::Error`, so `getrandom` is no longer part of the `cards-core` API (ADR 0015, part of #13).
- The app's toasts, alert dialogs, navigation, row menus and list focus go through shared helpers in `crates/app/src/ui/`. No visible change.
- Lints are silenced only with `#[expect(.., reason = "..")]` (workspace lints `allow_attributes`, `allow_attributes_without_reason`).
- Docs: README, CLAUDE.md and SPEC say what v0 already does; CLAUDE.md has rules on focus, stacked PRs and UI that cannot be seen.

### Removed
- `Store::due_cards` and `Store::new_cards` in `cards-core`: unused since `Store::study_input`.
